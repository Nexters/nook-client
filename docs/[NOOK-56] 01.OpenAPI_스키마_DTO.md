> 개발 서버의 OpenAPI 명세를 스냅샷으로 관리하고, Orval로 Web DTO와 API 함수를 생성하며,
> 서버 명세와 생성 코드가 일치하는지 검사하는 환경을 설명한다.

## API 계약을 가져오는 과정

기본 원본은 개발 서버가 제공하는 OpenAPI JSON이다.

```text
https://api-dev.everynook.co.kr/v3/api-docs
```

`pnpm api:refresh`를 실행하면 다음 과정이 순서대로 동작한다.

```text
개발 서버 /v3/api-docs
  → OpenAPI JSON 다운로드
  → 키 순서를 정렬해 스냅샷 저장
  → Orval이 스냅샷 해석
  → Web DTO·enum·API 함수 생성
```

다운로드한 명세는 `openapi/nook-dev.openapi.json`에 저장한다. 키를 정렬하는 이유는 서버가
같은 명세를 다른 순서로 반환해도 불필요한 Git diff가 생기지 않게 하기 위해서다.

Orval은 전체 명세의 `paths`와 `components.schemas`를 읽어 다음 코드를 만든다.

- 요청·응답 DTO
- 문자열 enum
- URL과 query parameter 생성 함수
- HTTP method와 body가 적용된 API 함수

현재 생성 대상은 Web TypeScript다. Kotlin·Swift 코드는 생성하지 않는다.

## 기존 API 계층 연결

Orval은 `fetch` client 형식으로 API 함수를 만들지만 브라우저 `fetch`를 직접 호출하지 않는다.
모든 생성 함수는 `orvalMutator`를 거쳐 기존 `apiFetch`와 `ApiClient`를 사용한다.

```text
Orval 생성 API 함수
  → orvalMutator
  → apiFetch
  → ApiClient
  → 서버
```

따라서 Base URL, timeout, 인증 헤더, HTTP 오류 변환은 기존 `ApiClient` 규칙을 그대로 따른다.
Base URL은 `VITE_API_BASE_URL`에서만 읽는다. Orval이 생성한 `/api/v1` 경로와 환경변수의 base
path가 중복되지 않도록 mutator가 상대 경로로 변환한다.

현재 서버 명세에는 인증 `securitySchemes`가 없다. 보호 API는 호출할 때 다음처럼 인증 옵션을
명시해야 한다.

```ts
await list({ auth: 'required' });
```

## 파일별 역할

```text
packages/api-contracts/
├── openapi/nook-dev.openapi.json
├── orval.config.ts
├── scripts/
│   ├── fetch-openapi.mjs
│   ├── check-generated.mjs
│   └── lib/
│       └── openapi.mjs
└── package.json

apps/web/src/shared/api/
├── generated/
│   ├── endpoints.generated.ts
│   └── models/
├── orval-mutator.ts
├── http.ts
└── index.ts
```

| 파일 | 역할 |
| --- | --- |
| `openapi/nook-dev.openapi.json` | 개발 서버에서 받은 OpenAPI 명세 스냅샷 |
| `orval.config.ts` | Orval 입력, 출력 경로, Fetch client와 mutator 설정 |
| `scripts/fetch-openapi.mjs` | 명세를 다운로드하고 정렬된 JSON으로 저장 |
| `scripts/check-generated.mjs` | Orval 재생성 전후를 비교해 생성 코드가 최신인지 검사 |
| `scripts/lib/openapi.mjs` | 명세 경로와 JSON 정렬 로직 제공 |
| `generated/endpoints.generated.ts` | Orval이 만든 URL 생성 함수와 API 함수 |
| `generated/models/` | Orval이 만든 요청·응답 DTO, enum, parameter 타입 |
| `orval-mutator.ts` | 생성 함수를 기존 `ApiClient`에 연결하고 API 경로를 정규화 |
| `http.ts` | Base URL, timeout, 인증 헤더와 HTTP 오류 처리 |
| `index.ts` | 생성 API 함수와 모델을 Web 공통 API 모듈에서 export |
| `packages/api-contracts/package.json` | Orval 버전과 다운로드·생성·검사 명령 정의 |

## 명령어

| 명령 | 역할 |
| --- | --- |
| `pnpm api:refresh` | 명세 다운로드와 Orval 코드 생성을 한 번에 실행 |
| `pnpm api:fetch` | 명세 스냅샷만 갱신 |
| `pnpm api:generate` | 현재 스냅샷으로 Orval 코드 재생성 |
| `pnpm api:check` | 스냅샷과 생성 코드의 일치 여부 검사 |
| `pnpm api:check:remote` | 개발 서버 명세와 스냅샷의 일치 여부까지 검사 |
| `pnpm check` | 생성 코드, lint, 타입, 테스트 전체 검사 |

## 관리 규칙

- 명세가 변경되면 `pnpm api:refresh`를 실행한다.
- OpenAPI 스냅샷과 `apps/web/src/shared/api/generated/`를 함께 커밋한다.
- `generated/` 아래 파일은 직접 수정하지 않는다.
- 수동 API 계층, mutator, Mapper는 `generated/` 밖에 작성한다.
- CI는 `pnpm api:check:remote`로 서버 명세 변경과 재생성 누락을 검출한다.
