## 브랜치 & 머지

MVP 단계에서는 `develop`을 쓰지 않으며, 히스토리를 깔끔하게 유지하기 위한 흐름을 제안함:

```
작업 브랜치 ──PR──▶ main   (Squash 머지)
```
- Pull Request 필수
  - `main`에 직접 push 금지.
  - 별도의 리뷰는 받지 않아도 됨.
- 머지는 **Squash** 로 통일.
- `develop`은 나중에 필요해지면 도입.

## 커밋 & PR

**커밋** — Conventional Commits, 한국어 본문:

```
<type>(<scope>): <제목>
```

- type: `feat` `fix` `refactor` `style` `docs` `test` `chore`
- 예: `chore(config): Biome 에디터 통합 설정 추가`

**PR** — 템플릿을 따르고, 관련 티켓을 본문에 적는다.

## main 보호 규칙

GitHub Ruleset `main_branch_protection`으로 강제 중:

| 규칙 | 설정 |
| --- | --- |
| PR 필수 (직접 push 금지) | ✅ |
| 승인 | 0명 |
| **CI 통과 필수** | ✅ (`verify`) |
| 삭제 / force-push 금지 | ✅ |

## CI — 로컬 vs 원격

로컬은 단계별로 가볍게, 원격(PR)이 전체를 돌리는 진짜 게이트.

| | pre-commit | pre-push | PR (CI) |
| --- | --- | --- | --- |
| 시점 | `git commit` | `git push` | `main`으로 PR |
| 포맷·린트 | `biome check` (staged) | — | `biome ci` (전체) |
| 타입체크 | — | `tsc --noEmit` | `tsc --noEmit` |
| 테스트 | ❌ | ❌ | `vitest run` |
| 빌드 | ❌ | ❌ | `vite build` |
| 실패하면 | 커밋 차단 | push 차단 | **main 머지 차단** |

- 네이티브(android/ios) 빌드는 무겁고 서명 시크릿이 필요해 CI 제외 → 배포 파이프라인에서 별도.
- 에디터는 `.vscode`로 Biome를 기본 포맷터 지정(저장 시 자동 포맷).
