## 진단 — 무엇이 진짜 계정 탓인가

Individual(개인) 멤버십 때문에 원천적으로 막힌 건 **하나뿐이다.**

> 다른 사람이 **자기 Apple ID 로 우리 번들 ID(`kr.co.everynook.app`)에 서명**하는 것.

팀원 추가가 불가능해서 Xcode 자동 서명이 동작하지 않는다. 여기까지가 계정의 한계다.

반면 아래는 계정 탓이 **아니다.** 우회 인프라를 아직 안 깔아서 생기는 비용이다.

- 기기 UDID 등록을 관리자가 대행해야 하는 것
- 새 기기마다 ad-hoc 프로파일을 다시 만드는 것
- 네이티브를 고칠 때마다 클라우드 빌드를 기다리는 것

즉 "구조적으로 구리다"는 절반만 맞다. 고칠 수 있는 부분이 남아 있다.

## 1. 시뮬레이터 — 가장 과소평가된 선택지

**코드 서명이 아예 필요 없다.** 인증서·프로파일·기기 등록·관리자 개입이 전부 0이다.
누구나 클론한 그날 바로 쓸 수 있고, EAS 무료 한도도 소모하지 않는다.

```bash
cd apps/mobile && pnpm ios      # --device 없이
```

첫 빌드 5~15분, 이후 증분 1~2분. **네이티브 개발의 기본 루프는 여기가 맞다.**

### 시뮬레이터에서 되는 것

| 기능 | 동작 | 비고 |
| --- | --- | --- |
| 공유 확장 (공유 시트) | O | |
| App Group (본앱 ↔ 확장 데이터) | O | 시뮬레이터는 프로파일 검증을 하지 않는다 |
| 카카오 로그인 | O | 카톡 앱이 없어 웹 로그인으로 넘어간다 |
| 애플 로그인 | O | 시뮬레이터에 iCloud 로그인이 돼 있어야 한다 |
| **푸시 알림** | O (조건부) | Xcode 14+ / Apple Silicon 맥이면 APNs 샌드박스로 실제 수신된다 |
| 카메라 | X | 실기기 필요 |

> **미검증**: 시뮬레이터의 APNs 토큰은 실기기와 형식이 달라서, 우리 FCM 경로가 그대로
> 먹는지 확인이 필요하다. 한 번 찍어보면 바로 갈린다.

### 그래서 실기기의 역할

"개발 루프"가 아니라 **최종 확인용**으로 내려간다. 카메라, 실제 푸시 수신, 성능처럼
시뮬레이터가 못 하는 것만 본다. 그 빈도라면 EAS 클라우드 빌드(2번)로도 충분하다.

## 5. fastlane match — 실기기 루프가 상시 필요할 때

정확히 이 문제(팀원을 포털에 넣을 수 없는데 서명은 해야 함)를 위해 만들어진 도구다.
인증서와 프로비저닝 프로파일을 **비공개 git 저장소에 암호화 저장**하고, 팀원은 명령
한 줄로 자기 맥에 설치한다.

```bash
fastlane match development --readonly
```

핵심은 `--readonly` 다. 이 모드에서는 **팀원에게 Apple 포털 접근도, ASC API 키도 필요 없다.**
저장소 접근 권한과 복호화 암호만 있으면 된다.

| | match 도입 전 | 도입 후 |
| --- | --- | --- |
| 신규 개발자 온보딩 | CSR 받기 → 인증서 발급 → 프로파일 2개 생성 → 파일 전달 | repo 초대 + 암호 전달 |
| 기기 추가 | 관리자가 프로파일 재생성 후 재배포 | 관리자가 한 번 갱신, 팀원은 `--readonly` 재실행 |
| 갱신·만료 | 수동 | 명령으로 처리 |

02 문서에 적어둔 "CSR 받아서 인증서 발급" 절차는 이걸 **손으로 하는 열등한 버전**이다.
match 를 도입하면 그 절차는 폐기해도 된다.

### 트레이드오프

- 개발용 인증서의 **개인키를 팀이 공유**하게 된다. 배포용 인증서는 EAS 에 그대로 두고
  **개발용만** match 에 넣으면 노출 범위가 작고, 문제가 생기면 폐기 후 재발급하면 된다
- 암호화 저장용 비공개 저장소가 하나 더 필요하다
- 최초 생성 시에만 ASC API 키가 필요하다 (관리자가 실행)

### 함께 필요한 작업

`expo run:ios` 는 매번 prebuild 로 Xcode 프로젝트를 새로 만들기 때문에 수동 서명 설정이
유지되지 않는다. `app.config.ts` 에 **환경변수가 있을 때만 수동 서명을 적용하는 config
plugin** 을 추가해야 한다. 관리자 환경에는 영향이 없도록 조건부로 켠다.

## 6. 로컬 전용 variant — 관리자 개입 0으로 실기기 빌드

`app.config.ts` 에 세 번째 variant 를 추가한다. **개발자 본인의 무료 Apple ID 와 본인
번들 ID** 로 빌드되는 축소판이다.

무료 Personal Team 은 App Group·애플 로그인·푸시 같은 특권을 프로비저닝해주지 못한다.
그래서 그 entitlement 들과 공유 확장 타깃을 **빼면** 서명이 통과한다.

| | 되는 것 | 안 되는 것 |
| --- | --- | --- |
| 로컬 variant | WebView, 웹 연동, 세션·키보드 모듈, 화면 전반 | App Group, 애플 로그인, 푸시, 공유 확장 |

- 등록도, 발급도, 관리자도 필요 없다. 클론하고 바로 실기기 빌드
- 무료 계정 서명이라 설치된 앱이 7일 뒤 만료된다 (재설치하면 된다)
- 구현은 `app.config.ts` 분기 몇 줄 + 번들 ID 를 env 로 받는 정도

entitlement 와 무관한 네이티브 작업(WebView 키보드 모듈, 세션 모듈 등)에는 이게 제일 깔끔하다.

## 추천 조합

| 상황 | 방법 | 관리자 개입 |
| --- | --- | --- |
| 네이티브 개발 기본 루프 | **1. 시뮬레이터** | 없음 |
| entitlement 무관한 네이티브를 실기기에서 | **6. 로컬 variant** | 없음 |
| 전 기능을 실기기에서 상시 | **5. match** | 최초 1회 |
| 푸시·공유확장 최종 검증 | **2. EAS ad-hoc 빌드** | 기기 등록 1회 |

지금 당장은 1번만으로도 대부분이 해결된다. 5·6번은 실기기 루프의 빈도가 실제로 높아졌을 때
투자하면 된다.
