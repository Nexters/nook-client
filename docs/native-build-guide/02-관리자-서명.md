# 관리자 서명 가이드

새 팀원을 온보딩하고 iPhone, 개발 인증서, 프로비저닝 프로파일을 관리하는 절차다. App Store Connect API 키를 가진 관리자만 수행할 수 있다.

## 1. 준비

셸 환경에 다음 값을 설정한다.

```bash
export EXPO_ASC_API_KEY_PATH="$HOME/my-projects/keys/nook/app-store-connect-L2F7D68453.p8"
export EXPO_ASC_KEY_ID="L2F7D68453"
export EXPO_ASC_ISSUER_ID="<Issuer ID>"
```

주요 명령은 레포 루트에서 실행한다.

| 작업 | 명령 | 결과 |
| --- | --- | --- |
| 기기 등록 | `pnpm ios:signing device <이름> <UDID>` | 개발 프로파일 2개 재생성 |
| 인증서 발급 | `pnpm ios:signing cert <CSR> [이름]` | `.cer`와 개발 프로파일 2개 |
| 프로파일 갱신 | `pnpm ios:signing profiles` | 개발 프로파일 2개 재생성 |

결과는 `apps/mobile/build/ios-signing`에 생성된다. EAS 개발 빌드용 ad-hoc 프로파일은 [EAS 실기기 가이드](03-EAS-실기기.md)를 따른다.

## 2. 새 팀원 온보딩

| # | 할 일 | 필요한 경우 |
| --- | --- | --- |
| 1 | GitHub `Nexters/nook-client` 초대 | 항상 |
| 2 | EAS `everynook` 계정에 Developer 이상으로 초대 | 항상 |
| 3 | `apps/web/.env.local` 값 전달 | 항상 |
| 4 | iPhone UDID 등록 | 실기기 설치 |
| 5 | 네이버 지도 콘솔에 팀원의 로컬 HTTPS 주소 등록 | 실기기에서 로컬 지도 확인 |
| 6 | CSR을 받아 개발 인증서와 프로파일 전달 | 팀원 Mac에서 iPhone 직접 빌드 |

1~3까지 마치면 웹과 시뮬레이터 개발을 시작할 수 있다. 4까지 마치면 EAS 개발 빌드를 설치할 수 있고, 6까지 마치면 `pnpm ios:device`를 사용할 수 있다.

## 3. 새 iPhone 등록

팀원에게 기기 이름과 UDID를 받는다. Finder 또는 다음 명령으로 UDID를 확인할 수 있다.

```bash
xcrun devicectl list devices
pnpm ios:signing device "<기기 이름>" <UDID>
```

이 명령은 개발 프로파일 두 개를 새 기기를 포함해 다시 만든다.

후속 작업:

- `pnpm ios:device`를 쓰는 팀원 전원에게 새 `.mobileprovision` 두 개를 전달한다.
- `dev-metro` 빌드를 설치할 기기라면 [EAS 실기기 가이드](03-EAS-실기기.md)에 따라 ad-hoc 프로파일도 갱신한다.

## 4. 개발 인증서 발급

팀원이 자신의 Mac에서 iPhone으로 직접 빌드할 때 필요하다.

1. 팀원에게 CSR 파일과 iPhone UDID를 받는다.
2. 기기가 미등록이면 먼저 3절을 수행한다.
3. 인증서를 발급한다.

```bash
pnpm ios:signing cert ~/Downloads/CertificateSigningRequest.certSigningRequest 홍길동
```

4. 다음 파일을 팀원에게 전달한다.

- `홍길동.cer`
- `Nook Development.mobileprovision`
- `Nook ShareExtension Development.mobileprovision`

5. 새 프로파일 두 개는 기존 실기기 개발자에게도 다시 전달한다.

CSR, `.cer`, `.mobileprovision`에는 개인키가 없으므로 팀 채널로 전달해도 된다. 개인키는 CSR을 만든 Mac의 키체인에만 남는다.

### 주의할 점

- 인증서는 Mac마다 하나가 필요하다. Mac이 바뀌면 CSR부터 다시 만든다.
- API가 발급한 인증서 이름은 모두 `Apple Development: Created via API (L2F7D68453)`이다. 발급 당시 파일 이름과 인증서 ID로 소유자를 구분한다.
- 인증서를 폐기하면 해당 인증서가 포함된 프로파일이 `INVALID`가 된다. 폐기 후 `pnpm ios:signing profiles`를 실행하고 새 프로파일을 배포한다.
- 프로비저닝 프로파일은 보통 1년 뒤 만료된다. 만료 전에 다시 생성해 배포한다.

## 5. EAS 환경변수 갱신

카카오 키나 Firebase 설정이 바뀌면 EAS 환경변수를 갱신한다. 팀원은 이후 `pnpm onboard`를 다시 실행하면 된다.

```bash
cd apps/mobile
pnpm exec eas env:list --environment development
pnpm exec eas env:create --environment development
```

production 환경도 같은 방식으로 관리한다.

| 이름 | 타입 | 환경 |
| --- | --- | --- |
| `GOOGLE_SERVICES_FILE_IOS` | 파일 | development와 production에 각각 등록 |
| `GOOGLE_SERVICES_FILE_ANDROID` | 파일 | 두 환경에서 공용 사용 |
| `KAKAO_NATIVE_APP_KEY_DEV`, `KAKAO_NATIVE_APP_KEY_PROD` | 문자열 | 두 환경에 등록 |

| variant | Bundle ID | Firebase 프로젝트 |
| --- | --- | --- |
| production | `kr.co.everynook.app` | `nook-aaa8b` |
| development | `kr.co.everynook.app.dev` | `thermal-camera-503912-j8` |

## 6. 계정 제약과 자격증명

Apple Developer 계정은 Individual 멤버십이다. 팀원을 Certificates, Identifiers & Profiles에 추가할 수 없으므로 관리자가 API 키로 기기와 인증서를 관리한다.

| 자격증명 | 보관 위치 | 다시 내려받기 |
| --- | --- | --- |
| Firebase 설정, 카카오 키 | EAS 환경변수 | 가능 |
| 배포 인증서와 개인키 | EAS credentials | 가능 |
| ad-hoc·App Store 프로파일 | EAS credentials | 가능 |
| App Store Connect API 키 `.p8` | 관리자 로컬 및 EAS 제출 설정 | EAS에서 불가 |
| APNs 푸시 키 `.p8` | Firebase | 불가 |

API 키·APNs 키 발급, App Groups 설정 등은 Account Holder가 웹에서 수행해야 한다.

## 7. 백업

`.p8` 파일은 Apple에서 다시 다운로드할 수 없다. Mac을 초기화하거나 교체하기 전에 키 디렉터리와 관련 환경변수를 안전한 장소에 백업한다. 인증서와 프로파일은 EAS 또는 Apple API로 복구할 수 있다.
