# 팀원 개발 가이드

처음 세팅한 뒤 웹·앱 JS·네이티브 코드를 개발하고 실기기에서 확인하는 방법이다. 관리자 작업은 [관리자 서명 가이드](02-관리자-서명.md), 실제 배포는 [App Store 배포 가이드](04-App-Store-배포.md)를 참고한다.

## 1. 처음 세팅하기

### 준비물

- Mac과 iPhone: 실기기 개발 시 같은 Wi-Fi에 연결
- Xcode: 시뮬레이터 또는 네이티브 빌드 시 필요
- CocoaPods: `brew install cocoapods`

웹만 개발한다면 Xcode와 CocoaPods는 나중에 설치해도 된다.

### 저장소 설치

```bash
git clone git@github.com:Nexters/nook-client.git
cd nook-client
nvm install
corepack enable
pnpm install
pnpm onboard
```

`pnpm onboard`는 웹 환경 파일을 만들고 EAS에서 카카오 키와 Firebase 설정을 내려받는다. `apps/web/.env.local` 값은 관리자에게 받는다. EAS의 `everynook` 프로젝트에도 초대되어 있어야 한다.

> `apps/mobile/.env.local`에는 `APPLE_TEAM_ID`를 넣지 않는다.

## 2. 평소 개발하기

### 로컬 웹과 앱 JS

```bash
pnpm dev
```

vite와 Metro가 함께 실행된다. iPhone의 개발 앱에서 표시된 개발 서버를 선택하면 코드 변경이 바로 반영된다.

| 연결할 웹 | 명령 |
| --- | --- |
| 내 Mac의 로컬 웹 | `pnpm dev` |
| 개발 웹 `app-dev.everynook.co.kr` | `pnpm dev:remote` |
| 지정한 웹 | `EXPO_PUBLIC_WEB_URL=https://example.com pnpm dev:remote` |

서버 주소나 Mac의 IP가 바뀌면 개발 서버를 다시 실행한다.

### 실기기 로컬 HTTPS

실기기에서 로컬 웹을 열려면 최초 한 번 인증서를 설정한다.

```bash
brew install mkcert
mkcert -install
ipconfig getifaddr en0
cd apps/web/certs
mkcert <MAC_IP> localhost 127.0.0.1
```

생성된 키와 인증서 경로를 `apps/web/.env.local`의 `DEV_HTTPS_KEY`, `DEV_HTTPS_CERT`에 넣는다. iPhone에 루트 인증서를 설치하고 신뢰하는 방법은 [인증서 안내](../../apps/web/certs/README.md)를 따른다.

- Mac IP가 바뀌면 새 IP를 포함해 인증서를 다시 만든다.
- 지도를 확인하려면 관리자에게 `https://<MAC_IP>:5173`을 네이버 지도 콘솔에 등록해 달라고 요청한다.

### 로그 확인

| 확인할 로그 | 방법 |
| --- | --- |
| 웹 콘솔·네트워크 | iPhone 웹 검사기와 Mac Safari 개발자용 메뉴 |
| 앱 JS | `pnpm dev`를 실행한 터미널 |
| Swift·네이티브 크래시 | macOS Console 앱에서 기기와 프로세스 선택 |
| 리로드 등 개발자 메뉴 | iPhone을 흔들기 |

iPhone: `설정 → 앱 → Safari → 고급 → 웹 검사기`  
Mac Safari: `Safari → 설정 → 고급 → 웹 개발자용 기능 보기`

## 3. 네이티브 개발하기

### 수정할 위치

| 변경 대상 | 위치 |
| --- | --- |
| 네이티브 모듈 | `apps/mobile/modules/*/ios/*.swift` |
| 공유 확장 | `apps/mobile/targets/share-target/*.swift` |
| 권한, 아이콘, 식별자, 플러그인 | `apps/mobile/app.config.ts` |

`apps/mobile/ios`는 다시 생성될 수 있다. Xcode는 실행과 디버깅에 사용하고 코드는 위 경로에서 수정한다.

### 방법 선택

| 방법 | 적합한 상황 | 소요 시간 |
| --- | --- | --- |
| 시뮬레이터 | 대부분의 네이티브 개발 | 첫 빌드 5~15분, 이후 1~2분 |
| 연결한 iPhone | 카메라·푸시·실제 성능을 반복 확인 | 첫 빌드 5~15분, 이후 1~2분 |
| EAS 개발 빌드 | 서명 파일 없이 실기기에서 최종 확인 | 보통 10~15분 이상 |

### 시뮬레이터

```bash
pnpm ios
```

먼저 `pnpm onboard`를 실행해야 한다. Firebase 설정 파일이 없으면 prebuild가 실패한다. Apple 계정이나 코드 서명은 필요 없다. `apps/mobile/ios/Nook.xcworkspace`를 Xcode에서 열면 브레이크포인트를 사용할 수 있다.

### 연결한 iPhone

최초 한 번 관리자에게 서명 파일을 받아야 한다.

1. iPhone을 Mac에 연결하고 Finder에서 UDID를 확인한다.
2. 키체인 접근에서 `인증서 지원 → 인증 기관에서 인증서 요청`을 선택한다.
3. 이메일을 입력하고 `디스크에 저장됨`을 선택해 CSR 파일을 만든다.
4. 관리자에게 기기 이름, UDID, CSR 파일을 보낸다.
5. 받은 `.cer` 하나와 `.mobileprovision` 두 개를 각각 더블클릭한다.

이후 iPhone을 연결하고 잠금을 해제한 뒤 실행한다.

```bash
pnpm ios:device
```

“신뢰하지 않는 개발자”가 표시되면 `설정 → 일반 → VPN 및 기기 관리`에서 신뢰한다. 인증서와 프로파일이 만료되면 관리자에게 새 파일을 받아 설치한다.

### EAS 개발 빌드

먼저 해당 iPhone의 UDID가 등록되어 있어야 한다.

```bash
pnpm --filter mobile build:ios:dev-metro
```

완료 후 QR 코드로 설치한다. JS가 내장되지 않으므로 실행할 때 Mac에서 `pnpm dev` 또는 `pnpm dev:remote`가 실행 중이어야 한다. 로컬 빌드는 클라우드 빌드 한도를 사용하지 않는다.

```bash
pnpm --filter mobile build:ios:dev-metro:local
```

새 기기 추가 절차는 [EAS 실기기 가이드](03-EAS-실기기.md)를 참고한다.

## 4. 자주 발생하는 문제

| 증상 | 확인할 것 |
| --- | --- |
| `Path to GoogleService-Info.plist is not defined` | `pnpm onboard` 후 prebuild 초기화 |
| 팀 개발 프로파일이 없다고 나옴 | 관리자가 준 프로파일 두 개의 설치 여부 |
| 선택한 기기가 프로파일에 없다고 나옴 | 관리자에게 UDID 등록과 새 프로파일 요청 |
| `No signing certificate` 또는 `no identity found` | `.cer` 설치 여부와 CSR을 만든 Mac인지 확인 |
| QR 설치 실패 | 해당 iPhone의 UDID 등록 여부 |
| 카카오 로그인 실패 | `pnpm onboard` 재실행 |
| 지도만 표시되지 않음 | 네이버 지도 키와 로컬 IP 등록 여부 |
| 로컬 웹 인증서 오류 | iPhone의 mkcert 루트 인증서 신뢰 여부와 URL의 IP |
| `pod install` 로케일 오류 | `export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` 후 재시도 |
| `ios` 수정이 사라짐 | 생성 폴더 대신 `modules`, `targets`, `app.config.ts` 수정 |

prebuild를 초기화하려면 다음을 실행한다.

```bash
cd apps/mobile
pnpm exec expo prebuild --clean
cd ../..
pnpm ios
```

## 5. 관리자에게 요청할 것

| 상황 | 요청 |
| --- | --- |
| 처음 합류 | GitHub 초대, EAS Developer 권한, `apps/web/.env.local` 값 |
| iPhone에 앱 설치 | 기기 이름과 UDID |
| 실기기에서 로컬 지도 확인 | `https://<MAC_IP>:5173` 등록 |
| Mac에서 iPhone 직접 빌드 | CSR을 보내고 `.cer` 하나와 프로파일 두 개 요청 |
