# 02. 관리자 작업

App Store Connect API 키를 가진 사람만 할 수 있는 일들이다.

## 준비

`~/.zshrc` 에 아래가 있어야 한다.

```bash
export EXPO_ASC_API_KEY_PATH="$HOME/my-projects/keys/nook/app-store-connect-L2F7D68453.p8"
export EXPO_ASC_KEY_ID="L2F7D68453"
export EXPO_ASC_ISSUER_ID="<Issuer ID>"
```

기기 등록·개발 인증서 발급·개발 프로파일 재생성은 이 키를 읽는 스크립트 하나로 한다.

```bash
pnpm ios:signing device <이름> <UDID>          # 기기 등록 + 개발 프로파일 재생성
pnpm ios:signing cert <CSR 파일> [<이름>]       # 팀원 개발 인증서 발급 + 개발 프로파일 재생성
pnpm ios:signing profiles                      # 개발 프로파일 2개 재생성 (만료 갱신 등)
```

결과 파일은 `apps/mobile/build/ios-signing/` 에 떨어진다. ad-hoc 프로파일(EAS 빌드용)은 별도 절차다 — [05](05-기기-등록과-adhoc-프로파일.md).
직접 API 를 부를 일이 있으면 JWT 발급 방법도 거기 있다.

## 배경 — 왜 관리자만 할 수 있나

우리 Apple Developer 계정은 **Individual(개인) 멤버십**(팀 ID `TDTGJZTB57`)이다. 팀원을 추가할 수
없고, 웹 포털은 계정 소유자(Account Holder)만 로그인할 수 있다. 관리자도 계정 소유자는 아니다.

관리자가 가진 것은 계정 소유자에게 받은 **App Store Connect API 키**(`.p8`, Key ID `L2F7D68453`)다.
이 키로 포털 로그인 없이 기기 등록·인증서 발급·프로파일 생성·앱 제출을 API 로 처리한다.
권한의 실체는 지위가 아니라 이 키 파일 하나다.

빌드용 자격증명은 EAS 가 보관하므로 클라우드 빌드와 `eas build --local` 은 팀원 맥에 서명
파일이 없어도 동작한다.

| 것 | EAS 에 있나 | 내려받을 수 있나 |
| --- | --- | --- |
| Firebase 설정 파일, 카카오 키 | 있음 (환경변수) | **예** — `eas env:pull` |
| 배포 인증서 + 개인키 | 있음 | **예** — `eas credentials` 에서 Download |
| ad-hoc / App Store 프로비저닝 프로파일 | 있음 | **예** — 위와 동일 |
| App Store Connect API 키 (`.p8`) | 제출용으로 등록됨 | **아니오** |
| APNs 푸시 키 (`.p8`) | Firebase 콘솔에 업로드됨 | **아니오** |

`.p8` 은 Apple 에서도 재다운로드가 안 된다. 잃으면 폐기 후 재발급뿐이므로 로컬 백업이 유일한 사본이다.

## 새 개발자 온보딩 체크리스트

| # | 할 일 | 비고 |
| --- | --- | --- |
| 1 | GitHub `Nexters/nook-client` 초대 | |
| 2 | EAS `everynook` 계정 초대 (Developer 이상) | 이걸로 카카오 키·Firebase 설정이 `pnpm onboard` 으로 자동 전달된다 |
| 3 | `apps/web/.env.local` 값 전달 | 전부 공개값. `VITE_NAVER_MAP_CLIENT_ID` 가 핵심 |
| 4 | 기기 UDID 등록 | 실기기에 설치하려면 필수. 기기당 1회 |
| 5 | (로컬 웹을 폰에서 볼 거면) 네이버 지도 콘솔에 그 개발자 LAN IP 등록 | 안 하면 지도 화면만 깨진다 |
| 6 | (실기기를 자기 맥에서 빌드할 사람이면) CSR 받아 개발 인증서 발급, 프로파일 2개와 함께 전달 | 아래 참고. 맥당 1회 |

1~3 이 끝나면 웹 개발은 바로 시작할 수 있다. 4 까지 하면 EAS 빌드로 실기기 확인, 6 까지 하면 실기기 증분 빌드까지 자립한다.

## 기기 등록 (UDID)

**기기당 한 번이면 끝이다.** 등록해서 프로파일을 갱신해두면 이후 모든 빌드에 자동 적용되고,
빌드할 때마다 다시 인증할 필요가 없다.

개발자에게 UDID 를 받는다 — 아이폰을 맥에 연결하고 Finder 사이드바에서 기기를 클릭한 뒤
이름 아래 정보를 클릭하면 나온다. 또는 `xcrun devicectl list devices`.

```bash
pnpm ios:signing device "<기기 이름>" <UDID>
```

등록과 동시에 개발 프로파일 2개를 새 기기 포함으로 다시 만든다. 새로 나온 `.mobileprovision` 2개를
**실기기 직접 빌드를 쓰는 팀원 전원**에게 다시 보낸다 (프로파일에 기기 목록이 박혀 있어서).
EAS 빌드(ad-hoc)로 깔 기기면 ad-hoc 프로파일도 갱신한다 — [05](05-기기-등록과-adhoc-프로파일.md) 3절.

> 프로비저닝 프로파일은 발급 후 1년이면 만료된다. 그때 `pnpm ios:signing profiles` 로 다시 만들어 배포한다.

## 개발 인증서·프로파일 발급

팀원이 자기 맥에서 `pnpm ios:device` 로 실기기에 직접 빌드하려면 필요하다 ([팀원 지침서 3-C](01-팀원-지침서.md)).
EAS 에 있는 프로파일은 ad-hoc(배포용)이라 디버거 권한(`get-task-allow`)이 없어 개발 빌드에 못 쓴다.

**동작 원리** — 인증서는 "이 사람이 서명했다" 를 증명하고, 그 짝인 개인키는 팀원 맥에서만 만들어져 밖으로
나가지 않는다. 팀원이 CSR(인증서 요청 파일)을 보내면 관리자가 API 로 인증서를 발급하고, 개발 프로파일 2개
(본앱 + ShareExtension)에 **모든 개발 인증서와 모든 기기**를 넣어 다시 만든다. 그래서 프로파일은 팀 공용
파일 2개뿐이고, 인증서만 사람마다 하나씩이다.

1. 팀원에게 CSR 파일(`.certSigningRequest`)과 폰 UDID 를 받는다. 만드는 법은 팀원 지침서 3-C. 둘 다 비밀 아님
2. 기기가 미등록이면 먼저 `pnpm ios:signing device …`
3. 인증서를 발급한다:
   ```bash
   pnpm ios:signing cert ~/Downloads/CertificateSigningRequest.certSigningRequest 홍길동
   ```
4. `apps/mobile/build/ios-signing/` 의 `홍길동.cer`, `Nook Development.mobileprovision`,
   `Nook ShareExtension Development.mobileprovision` 을 보낸다. 셋 다 비밀이 아니라 Slack 이면 된다.
   프로파일 2개는 **기존 팀원에게도** 다시 보낸다 (새 인증서가 들어간 새 프로파일이라)

인증서는 맥마다 하나다. 팀원이 맥을 바꾸면 CSR 을 새로 받아 3~4 를 반복한다. 옛 인증서는
`DELETE /v1/certificates/{id}` 로 폐기해도 되고, 두어도 무해하다.

`app.config.ts` 는 맥에 `Nook Development` / `Nook ShareExtension Development` 프로파일이 설치돼 있을 때만
두 타깃을 그걸로 수동 서명한다 (`native-public-config.json` 의 `ios.devProfiles`). 관리자 맥에도 같은
프로파일을 설치해두면 관리자도 `pnpm ios:device` 로 빌드된다 — 관리자 맥의 개발 인증서(`Apple Development: Created via API`)도 프로파일에 들어 있다.

## 환경변수·설정 파일 갱신

카카오 키나 Firebase 설정 파일이 바뀌면 EAS 에 올린다. 개발자들은 `pnpm onboard` 만 다시
돌리면 된다.

```bash
cd apps/mobile
pnpm exec eas env:list --environment development         # 현재 등록 상태 확인 (production 도 같음)
pnpm exec eas env:create --environment development       # 대화형으로 등록
```

로컬 개발(`pnpm onboard`)과 `dev-metro` 는 development 환경을, `prod-store` 는 production 환경을 읽는다.

현재 등록 상태:

| 이름 | 타입 | 환경 |
| --- | --- | --- |
| `GOOGLE_SERVICES_FILE_IOS` | 파일 | production / development **각각 별도** (번들 ID 가 달라서) |
| `GOOGLE_SERVICES_FILE_ANDROID` | 파일 | 두 환경 공용 1개 (한 파일에 두 패키지가 다 들어있다) |
| `KAKAO_NATIVE_APP_KEY_DEV` / `_PROD` | 문자열 | 두 환경 모두 |

Firebase 프로젝트 대응:

| variant | 번들 ID | Firebase 프로젝트 |
| --- | --- | --- |
| production | `kr.co.everynook.app` | `nook-aaa8b` |
| development | `kr.co.everynook.app.dev` | `thermal-camera-503912-j8` |

## API 로 할 수 없는 것

| 작업 | 이유 | 대안 |
| --- | --- | --- |
| API 키 발급·폐기 | `/v1/authKeys` 가 404 | 계정 소유자가 웹 포털에서 |
| APNs 푸시 키 발급 | `/v1/pushCertificates` 가 404 | 계정 소유자가 웹 포털에서 |
| App Groups 설정 | API 미지원 | 계정 소유자가 웹 포털에서 |
| 팀원 추가 | Individual 멤버십은 불가 | 없음 |

## 백업

`.p8` 키 파일들은 Apple 에서 재다운로드가 안 된다. 맥을 초기화하기 전에 반드시 백업한다.

```bash
cp -R ~/my-projects/keys/nook <백업 위치>
grep -A3 "Nook expo 배포" ~/.zshrc
```

인증서·프로파일은 EAS 에서 다시 내려받을 수 있어 백업이 필요 없다.
