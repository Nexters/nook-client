# 02. 관리자 작업

App Store Connect API 키를 가진 사람만 할 수 있는 일들이다.

## 준비

`~/.zshrc` 에 아래가 있어야 한다.

```bash
export EXPO_ASC_API_KEY_PATH="$HOME/my-projects/keys/nook/app-store-connect-L2F7D68453.p8"
export EXPO_ASC_KEY_ID="L2F7D68453"
export EXPO_ASC_ISSUER_ID="<Issuer ID>"
```

모든 API 호출은 이 키로 만든 JWT 를 `Authorization: Bearer` 헤더에 넣는다. JWT 발급
스크립트는 [05 문서 3-1](05-기기-등록과-adhoc-프로파일.md) 에 있다.

## 배경 — 왜 관리자만 할 수 있나

우리 Apple Developer 계정은 **Individual(개인) 멤버십**(팀 ID `TDTGJZTB57`)이다. 팀원을 추가할 수
없고, 웹 포털은 계정 소유자(Account Holder)만 로그인할 수 있다. 관리자도 계정 소유자는 아니다.

관리자가 가진 것은 계정 소유자에게 받은 **App Store Connect API 키**(`.p8`, Key ID `L2F7D68453`)다.
이 키로 포털 로그인 없이 기기 등록·인증서 발급·프로파일 생성·앱 제출을 API 로 처리한다.
권한의 실체는 지위가 아니라 이 키 파일 하나다.

빌드용 자격증명은 EAS 가 보관하므로 클라우드 빌드와 `eas build --local` 은 팀원 맥에 서명
파일이 없어도 동작한다.

| 것 | EAS 에 있나 | 내려받을 수 있나 |
| --- | --- | --- |
| Firebase 설정 파일, 카카오 키 | 있음 (환경변수) | **예** — `eas env:pull` |
| 배포 인증서 + 개인키 | 있음 | **예** — `eas credentials` 에서 Download |
| ad-hoc / App Store 프로비저닝 프로파일 | 있음 | **예** — 위와 동일 |
| App Store Connect API 키 (`.p8`) | 제출용으로 등록됨 | **아니오** |
| APNs 푸시 키 (`.p8`) | Firebase 콘솔에 업로드됨 | **아니오** |

`.p8` 은 Apple 에서도 재다운로드가 안 된다. 잃으면 폐기 후 재발급뿐이므로 로컬 백업이 유일한 사본이다.

## 새 개발자 온보딩 체크리스트

| # | 할 일 | 비고 |
| --- | --- | --- |
| 1 | GitHub `Nexters/nook-client` 초대 | |
| 2 | EAS `everynook` 계정 초대 | 이걸로 카카오 키·Firebase 설정이 `eas env:pull` 로 자동 전달된다 |
| 3 | `apps/web/.env.local` 값 전달 | 전부 공개값. `VITE_NAVER_MAP_CLIENT_ID` 가 핵심 |
| 4 | 기기 UDID 등록 | 실기기에 설치하려면 필수. 기기당 1회 |
| 5 | (로컬 웹을 폰에서 볼 거면) 네이버 지도 콘솔에 그 개발자 LAN IP 등록 | 안 하면 지도 화면만 깨진다 |
| 6 | (네이티브를 자주 만질 사람이면) Development 인증서·프로파일 발급 | 아래 참고. **미구축** |

1~3 이 끝나면 웹 개발은 바로 시작할 수 있다. 4 까지 하면 실기기 확인까지 자립한다.

## 기기 등록 (UDID)

**기기당 한 번이면 끝이다.** 등록해서 프로파일을 갱신해두면 이후 모든 빌드에 자동 적용되고,
빌드할 때마다 다시 인증할 필요가 없다.

개발자에게 UDID 를 받는다 — 아이폰을 맥에 연결하고 Finder 사이드바에서 기기를 클릭한 뒤
이름 아래 정보를 클릭하면 나온다. 또는 `xcrun devicectl list devices`.

이후 절차(등록 → ad-hoc 프로파일 재생성 → EAS 재업로드)는
[05. 기기 등록과 ad-hoc 프로파일](05-기기-등록과-adhoc-프로파일.md) 3절 을 그대로 따른다.

> 프로비저닝 프로파일은 발급 후 1년이면 만료된다. 그때 한 번 재생성이 필요하다.

## Development 인증서·프로파일 발급 (미구축)

> ⚠️ **아직 만들지 않은 절차다.** 아래는 설계이고 검증되지 않았다.
> 목적은 다른 개발자도 `expo run:ios --device` 로 1~2분 증분 빌드를 하게 하는 것이다
> ([팀원 지침서 3-C](01-팀원-지침서.md)). fastlane match 를 도입하면 이 수동 절차는 폐기한다
> ([03](03-개발-환경-선택지-검토.md)).

지금 EAS 에 있는 프로파일은 ad-hoc(배포용)이라 디버거 권한(`get-task-allow`)이 꺼져 있어
개발 빌드에 쓸 수 없다. **Development 종류를 따로 발급**해야 한다.

1. 개발자가 맥 "키체인 접근 › 인증서 지원 › 인증 기관에서 인증서 요청"으로 CSR 파일을
   만들어 전달한다. 개인키는 개발자 맥에 남는다
2. 관리자가 `POST /v1/certificates` 로 CSR 을 올려 `DEVELOPMENT` 인증서를 발급한다
3. `POST /v1/profiles` 로 `IOS_APP_DEVELOPMENT` 프로파일을 **두 개** 만든다 —
   `kr.co.everynook.app` 과 `kr.co.everynook.app.ShareExtension`. `devices` 에 등록된
   기기 전체를 넣는다
4. 인증서와 프로파일 파일을 전달한다
5. 개발자가 설치하고 수동 서명으로 빌드한다

함께 해야 할 작업: prebuild 가 Xcode 프로젝트를 매번 새로 만들기 때문에 수동 서명 설정이
유지되지 않는다. `app.config.ts` 에 **config plugin 을 추가해 환경변수가 있을 때만
수동 서명을 적용**하도록 만들어야 한다.

리소스 ID 조회와 프로파일 생성 요청 형식은 ad-hoc 절차와 같으므로
[05 문서 3-3](05-기기-등록과-adhoc-프로파일.md) 을 재사용한다
(`profileType` 만 `IOS_APP_ADHOC` → `IOS_APP_DEVELOPMENT`).

## 환경변수·설정 파일 갱신

카카오 키나 Firebase 설정 파일이 바뀌면 EAS 에 올린다. 개발자들은 `eas env:pull` 만 다시
돌리면 된다.

```bash
cd apps/mobile
pnpm exec eas env:list --environment production          # 현재 등록 상태 확인
pnpm exec eas env:create --environment production        # 대화형으로 등록
```

현재 등록 상태:

| 이름 | 타입 | 환경 |
| --- | --- | --- |
| `GOOGLE_SERVICES_FILE_IOS` | 파일 | production / development **각각 별도** (번들 ID 가 달라서) |
| `GOOGLE_SERVICES_FILE_ANDROID` | 파일 | 두 환경 공용 1개 (한 파일에 두 패키지가 다 들어있다) |
| `KAKAO_NATIVE_APP_KEY_DEV` / `_PROD` | 문자열 | 두 환경 모두 |

Firebase 프로젝트 대응:

| variant | 번들 ID | Firebase 프로젝트 |
| --- | --- | --- |
| production | `kr.co.everynook.app` | `nook-aaa8b` |
| development | `kr.co.everynook.app.dev` | `thermal-camera-503912-j8` |

## API 로 할 수 없는 것

| 작업 | 이유 | 대안 |
| --- | --- | --- |
| API 키 발급·폐기 | `/v1/authKeys` 가 404 | 계정 소유자가 웹 포털에서 |
| APNs 푸시 키 발급 | `/v1/pushCertificates` 가 404 | 계정 소유자가 웹 포털에서 |
| App Groups 설정 | API 미지원 | 계정 소유자가 웹 포털에서 |
| 팀원 추가 | Individual 멤버십은 불가 | 없음 |

## 백업

`.p8` 키 파일들은 Apple 에서 재다운로드가 안 된다. 맥을 초기화하기 전에 반드시 백업한다.

```bash
cp -R ~/my-projects/keys/nook <백업 위치>
grep -A3 "Nook expo 배포" ~/.zshrc
```

인증서·프로파일은 EAS 에서 다시 내려받을 수 있어 백업이 필요 없다.
