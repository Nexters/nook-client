> 연결된 아이폰에서 앱을 띄우고, 코드를 고치면 바로 반영되고, 로그를 보면서 개발하는
> 방법을 처음부터 정리한다. 웹 개발할 때 / 네이티브 개발할 때 / 완성본을 통째로 빌드할 때가
> 각각 다르므로 상황별로 문서를 나눴다.

## 이 앱의 구조 (이것만 알면 나머지가 이해된다)

```
[아이폰]
 └ Nook 앱 (Expo 셸)  ← 얇은 껍데기. 카메라·푸시·공유 같은 네이티브 기능 담당
    └ WebView         ← 화면의 대부분. 여기에 웹(apps/web)이 그려진다
```

앱은 껍데기고 **화면 본체는 웹**이다. 그래서 "코드를 고쳤을 때 무슨 일이 일어나는가"가 세 갈래다.

| 고친 것 | 어디 | 앱을 다시 빌드해야 하나 | 반영 속도 |
| --- | --- | --- | --- |
| 웹 화면 | `apps/web/` | **아니오** | 저장 즉시 |
| 셸 JS/TS | `apps/mobile/src/` | **아니오** | 저장 즉시 |
| 네이티브 | `apps/mobile/modules/`, `targets/`, `app.config.ts` | **예** | 빌드 시간만큼 |

일상 작업의 대부분은 위 두 줄이라 빌드가 아예 없다. 빌드 얘기는 세 번째 줄에서만 나온다.

## 용어

| 말 | 뜻 |
| --- | --- |
| **Metro** | 셸의 JS 를 실시간으로 폰에 밀어넣는 개발 서버. 맥에서 띄우고 폰이 Wi-Fi 로 붙는다 |
| **dev client** | JS 를 내장하지 않고 Metro 에서 받아 실행하는 개발용 앱. 한 번 깔면 JS 변경은 빌드 없이 반영된다 |
| **prebuild** | `app.config.ts` 를 읽어 `ios/`·`android/` 네이티브 프로젝트를 **생성**하는 단계. 이 폴더들은 생성물이라 커밋하지 않는다 |
| **UDID** | 아이폰 한 대를 가리키는 고유 번호 |
| **프로비저닝 프로파일** | "이 앱을, 이 인증서로 서명해, 이 기기들에 설치해도 된다"를 적어 Apple 이 발급한 파일 |
| **인증서(Certificate)** | 서명하는 사람이 누구인지 증명하는 파일. 짝이 되는 개인키가 맥 키체인에 있어야 쓸 수 있다 |
| **entitlement** | 앱이 쓰겠다고 선언하는 특권(푸시, App Group, 애플 로그인 등). 프로파일에 같은 게 켜져 있어야 설치된다 |
| **ad-hoc** | 등록된 기기에만 설치되는 배포 방식. 우리 실기기 개발 빌드가 이걸 쓴다 |
| **EAS** | Expo 의 클라우드 서비스. 빌드를 대신 돌려주고 서명 자격증명을 보관한다 |
