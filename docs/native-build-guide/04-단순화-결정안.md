> [NOOK-332 모바일 개발 환경 단순화 리서치](https://linear.app/nooknook/issue/NOOK-332) 의 산출물.
> 지금 구조를 훑고, 안 쓰이는 것을 가려내고, **무엇을 없애고 무엇을 남길지**를 영향 범위·되돌리기와
> 함께 적는다. 이 문서에서는 코드를 고치지 않는다. 후속 티켓 초안은 6절.

## 1. 개발을 시작하려면 지금 알아야 하는 것

| 종류 | 개수 | 내용 |
| --- | --- | --- |
| 실행 명령 | 5 | `web:dev`, `mobile:start`, `mobile:start:dev`, `mobile:start:prod`, `ios` |
| 빌드 명령 | 10 | `build:{dev,prod}-{metro,store}` ×2(클라우드/`:local`), `submit:{dev,prod}-store` |
| EAS 빌드 프로필 | 4 | `dev-metro` `prod-metro` `dev-store` `prod-store` |
| variant | 2 | `development` / `production` — 번들 ID, Firebase 프로젝트, 카카오 키, 아이콘, 웹 URL, ASC 앱이 각각 2벌 |
| 로컬 설정값 | 7 | `APP_VARIANT` `APPLE_TEAM_ID` `KAKAO_*` ×2 `EXPO_PUBLIC_WEB_URL` + 웹 `VITE_*` |
| 값의 출처 | 3 | 커밋된 `native-public-config.json`, EAS env(`eas env:pull`), 로컬 `.env.local` |
| 빌드 방식 | 4 | 클라우드 / `eas build --local` / `expo run:ios --device` / 시뮬레이터 |
| 문서 | 3 → (이번 정리 후) | `ops/` 3개가 로컬·배포·제출로 나뉘어 있었고, 로컬 가이드의 서명 서술은 낡아 있었다 |

핵심 문제는 **내부 구현 용어가 그대로 명령 이름**이라는 점이다. `start:prod` 를 고르려면 variant 와
Metro 가 무엇인지 먼저 알아야 하고, `prod-metro` 를 고르려면 dev client 개념을 알아야 한다.

## 2. 팀원이 실제로 막힌 지점

이번 리서치 기간에 수집한 것들이다.

| 증상 | 원인 |
| --- | --- |
| Xcode 팀 목록에 Nook 이 없고 인증서에 X | Individual 계정이라 팀원 추가 불가 + `.env.example` 의 `APPLE_TEAM_ID` 를 채워 프로젝트가 우리 팀으로 고정됨 |
| "Metro 가 뭐고 EAS 가 뭐냐" | 셸+웹 이중 구조와 클라우드 빌드 개념이 명령 이름에 그대로 노출 |
| `GoogleService-Info.plist` 를 어디서 받나 | EAS file env 로 올라가 있지만 `eas env:pull` 로 받는다는 사실이 문서에 없었다 |
| "한 줄 고치면 15분 빌드해야 하나" | 웹·JS 는 빌드가 없다는 것, 네이티브는 시뮬레이터에서 증분 빌드한다는 것이 정리돼 있지 않았다 |
| 실기기가 기본인 줄 알고 시작 | 시뮬레이터가 서명 없이 되는 기본 루프라는 안내가 없었다 |

## 3. 안 쓰이는 것

### development variant

| 근거 | 확인 |
| --- | --- |
| 현재 프로필명(`dev-metro`, `dev-store`)으로 빌드된 기록 | **0건** (최근 30건 중 `prod-store` 3건, 나머지는 구 프로필명) |
| `app-dev.everynook.co.kr` 참조 | `native-public-config.json` 한 곳. 다른 코드·문서에서 미참조 |
| README | "별도 개발 서버를 운영하지 않아 현재는 production 만 사용한다" 고 이미 명시 |

variant 축은 위 1절 표의 거의 모든 행을 두 배로 만든다. 걷어내면 외울 것이 절반이 된다.

### `.env.example` 의 `APPLE_TEAM_ID`

로컬 실행(시뮬레이터)에는 필요 없고, EAS 빌드는 `eas.json` 의 `base.env` 에서 따로 주입한다.
예시 파일에 남아 있어 팀원이 채웠고, 그게 2절 첫 줄의 원인이 됐다.

### 낡은 문서

`ops/로컬_앱_빌드_가이드.md` 의 "Personal Team 으로 서명하면 된다"는 App Group·푸시·애플 로그인
entitlement 가 붙기 전 기준이라 지금은 동작하지 않는다. **이번 티켓에서 삭제하고 [팀원 지침서](01-팀원-지침서.md)로 대체했다.**

## 4. 결정안 — 무엇을 없애고 무엇을 남기나

### 없앨 것

| 대상 | 구체적으로 | 영향 범위 | 되돌리기 |
| --- | --- | --- | --- |
| **dev variant 표면** | `eas.json` 의 `dev-metro`·`dev-store`·`submit.dev-store`, `package.json` 의 `start:dev`·`build:dev-*`·`submit:dev-store`, `metro.sh` 의 variant 인자 | 팀원이 보는 명령·프로필이 절반으로. `app.config.ts` 분기·`native-public-config.json` 의 development 값·EAS development 환경 변수·Firebase dev 프로젝트·ASC dev 앱(6803065807)은 **그대로 두어** 필요 시 되살린다 | `git revert` 한 번. 외부 리소스는 안 지우므로 복구 대상 없음 |
| **`.env.example` 의 `APPLE_TEAM_ID`** | 행 삭제 | 없음 — EAS 는 `eas.json base.env` 로 주입 | `git revert` |
| **명령 이름의 구현 용어** | 루트에 `setup` / `dev` / `dev:remote` 3개로 통합. `dev` 는 vite + Metro 동시 기동, 맥 IP 를 알아내 `EXPO_PUBLIC_WEB_URL` 을 셸 변수로 넘김(#172 방식 그대로). 기존 `mobile:start*`·`web:dev` 는 한 릴리스 동안 alias 로 남기고 제거 | 팀원이 외울 명령이 2개(`setup`, `dev`) | 스크립트 변경만이라 `git revert` |
| **문서 중복** | `ops/로컬_앱_빌드_가이드` 삭제, `ops/` 의 모바일 문서 2개를 이 폴더로 이동(05·06), 임시 분할본 5개를 01 로 통합 | — | **이번 티켓에서 완료** |

### 남길 것

| 대상 | 이유 |
| --- | --- |
| `prod-store` 프로필, `submit.prod-store`, `base.env.APPLE_TEAM_ID`, `autoIncrement` remote | 스토어 빌드·제출 경로. 건드리지 않는다 |
| `prod-metro` 프로필 | 실기기 dev client 의 유일한 경로 |
| `app.config.ts` 의 variant 분기 | 코드 삭제 없이 표면만 걷어내 되살릴 수 있게 |
| EAS env 4개(`GOOGLE_SERVICES_FILE_*`, `KAKAO_*`), development 환경 포함 | 있어도 무해하고 지우면 복구가 번거롭다 |
| `metro.sh` 의 `EXPO_PUBLIC_WEB_URL` 우선 방식 (#172) | 새 `pnpm dev` 가 이 방식을 그대로 쓴다 |
| [05. 기기 등록과 ad-hoc 프로파일](05-기기-등록과-adhoc-프로파일.md) | 기기 등록 API 절차의 유일한 원본. [02](02-관리자-작업.md) 가 참조 |
| Individual 계정·서명 체계 | 이 티켓 범위 밖. 선택지는 [03](03-개발-환경-선택지-검토.md) |

### 기본 루프 선언

**네이티브 개발은 시뮬레이터(`pnpm ios`)가 기본**이고 실기기는 확인용이다. 팀원 지침서에 그렇게
못 박았다. 실기기 네이티브 루프가 실제로 잦아지면 03 의 fastlane match 를 별건으로 도입한다.

## 5. 스토어 빌드·제출에 영향이 가는 지점

미리 드러내야 하는 것들이다. 아래를 지키면 스토어 흐름은 변하지 않는다.

| 지점 | 주의 |
| --- | --- |
| `eas.json base.env.APPLE_TEAM_ID` | **삭제 금지.** `.env.example` 의 것과 혼동해 같이 지우면 EAS 빌드 서명 팀이 사라진다 |
| `submit.dev-store` 삭제 | ASC 의 dev 앱(6803065807)은 남는다. 앱 자체를 지우지 않는다 |
| 명령 alias 제거 시점 | `build:prod-store` / `submit:prod-store` 는 alias 가 아니라 **그대로 유지**한다 — 릴리스 절차 문서([06](06-App-Store-제출.md))가 이 이름을 쓴다 |
| `metro.sh` 변경 | 스토어 빌드는 Metro 를 쓰지 않아 무영향 |
| EAS environment 이름 | 프로필의 `environment: production` 은 그대로. env 변수 매핑이 바뀌지 않는다 |

## 6. 후속 티켓 초안

### A. 모바일 개발 환경 단순화 — dev variant 표면 제거·명령 통합

```
## 목적
* NOOK-332 결정안(docs/native-build-guide/08) 의 "없앨 것" 을 실행한다.

## 범위
* eas.json 의 dev-metro·dev-store·submit.dev-store 와 package.json 의 dev 계열 스크립트 삭제. app.config.ts 분기와 외부 리소스는 유지
* 루트 명령 setup / dev / dev:remote 추가. dev 는 vite+Metro 동시 기동, 맥 IP 로 EXPO_PUBLIC_WEB_URL 을 셸 변수로 전달 (#172 방식)
* apps/mobile/.env.example 에서 APPLE_TEAM_ID 삭제
* 기존 mobile:start*·web:dev 는 한 릴리스 alias 후 제거 예고
* 팀원 지침서(01)의 명령을 새 이름으로 갱신

## 제외 범위
* 서명 체계(fastlane match) — 별도 티켓
* eas.json base.env.APPLE_TEAM_ID, prod-store 프로필, submit:prod-store — 건드리지 않는다

## 성공 기준
* 클론한 신규 개발자가 pnpm setup → pnpm dev 로 시뮬레이터에 앱을 띄우고 웹 수정이 즉시 반영된다
* build:prod-store / submit:prod-store 가 이전과 동일하게 동작한다
* APPLE_TEAM_ID 가 .env.example 에 없다
```

### B. fastlane match 로 팀원 실기기 증분 빌드 열기

```
## 목적
* 팀원이 자기 맥에서 expo run:ios --device 로 1~2분 증분 빌드를 하게 한다. 현재는 Individual 계정 제약으로 불가.

## 범위
* 개발용 인증서·IOS_APP_DEVELOPMENT 프로파일(본앱 + ShareExtension)을 match 로 발급·비공개 저장소에 보관
* 팀원은 match --readonly 로 설치. Apple 계정·ASC 키 불필요
* app.config.ts 에 환경변수가 있을 때만 수동 서명을 적용하는 config plugin 추가 (prebuild 가 서명 설정을 덮어쓰는 문제)
* 팀원 지침서 3-C 를 "미구축" 에서 절차로 교체

## 제외 범위
* 배포용 인증서 — EAS 에 그대로 둔다
* 기기 UDID 등록 절차 변경 — 기존 ASC API 절차 유지

## 성공 기준
* 팀원 맥에서 pnpm ios --device 가 서명 오류 없이 폰에 설치되고, 두 번째 빌드가 2분 이내
* 관리자 맥의 기존 빌드 흐름에 영향이 없다
```

## 7. 이 티켓에서 이미 한 것

- 팀원 지침서(01), 관리자 작업(02), 선택지 검토(03), 이 결정안(04) 작성

- 위 표의 근거 수집 — EAS 빌드 기록, env 변수 목록, `eas env:pull` 동작 검증, #172 반영
