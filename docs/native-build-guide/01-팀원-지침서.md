## 0. 먼저 — 이 앱이 뭔지

**우리 사이트만 열리는 전용 브라우저**다.

크롬이 네이버를 보여주듯, 우리 앱은 우리 웹(`apps/web`)을 받아와 보여준다. 화면은 앱 안에
없고 웹에 있다. 앱 자체에는 웹이 혼자 못 하는 얇은 기능만 들어있다 — 카메라, 푸시 알림,
다른 앱에서 공유받기, 로그인 세션 보관.

그래서 하는 일이 세 종류로 갈린다.

| 하는 일 | 고치는 곳 | 앱을 다시 만드나 |
| --- | --- | --- |
| 화면 고치기 | `apps/web/` | **아니오.** 저장하면 폰 화면이 바뀐다 |
| 앱 껍데기 JS 고치기 | `apps/mobile/src/` | **아니오.** 저장하면 바뀐다 |
| 네이티브 고치기 | `apps/mobile/modules/`, `targets/`, `app.config.ts` | **예.** 이때만 빌드 |

앞의 둘이 일의 대부분이고, **앱을 다시 만드는 일은 셋째 줄에서만 생긴다.**

이름 두 개만 알면 된다.

- **Metro / vite** — 맥에서 켜두는 서버. 폰의 앱이 이걸 보고 화면을 그린다. vite 는 웹, Metro 는 앱 껍데기 JS 담당. 코드를 저장하면 화면이 바뀌는 건 이 둘 덕분이다.
- **EAS** — 앱(전용 브라우저 자체)을 대신 만들어주는 Expo 의 클라우드. 네이티브를 고쳤을 때만 간다.

## 1. 처음 세팅 (한 번)

### 준비물

| 것 | 설치 | 언제 필요 |
| --- | --- | --- |
| 맥, 아이폰 | 폰과 맥이 **같은 Wi-Fi** | 항상 |
| Xcode | App Store. 용량이 크니 먼저 걸어둔다 | 시뮬레이터·네이티브 빌드 (3절) |
| CocoaPods | `brew install cocoapods` | 같음 |

웹만 만질 거면 Xcode 없이도 시작할 수 있다. 네이티브 개발을 하려면 필요하다.

### 레포

```bash
git clone git@github.com:Nexters/nook-client.git && cd nook-client
nvm install
corepack enable
pnpm install
```

### 값 채우기 — 명령 한 줄

```bash
pnpm onboard
```

하는 일: `apps/web/.env.local` 을 예시에서 만들고(값은 관리자에게 받아 채운다 — `VITE_NAVER_MAP_CLIENT_ID`
가 없으면 지도가 안 뜬다), EAS 에 로그인해 카카오 키와 Firebase 설정 파일을 `apps/mobile/.env.local`
로 내려받는다. EAS 계정에 초대돼 있어야 한다.

> `apps/mobile/.env.local` 에 `APPLE_TEAM_ID` 는 넣지 않는다 — 넣으면 Xcode 서명이 깨진다 (FAQ 첫 항목).

## 2. 실기기에서 개발하기 + 서버 갈아타기

### 2-1. 폰에 앱 한 번 깔기

폰에 앱을 깔려면 Apple 허가증에 그 폰이 등록돼 있어야 한다. **폰 한 대당 한 번**이다.

1. 아이폰을 맥에 케이블로 연결 → Finder 사이드바에서 기기 클릭 → 이름 아래 정보를 **클릭**하면
   UDID 가 나온다. 기기 이름과 함께 관리자에게 전달
2. 관리자가 등록을 끝내면 둘 중 하나로 깐다:

| 방법 | 명령 | 시간 | 조건 |
| --- | --- | --- | --- |
| **내 맥에서 직접** | `pnpm ios:device` | 첫 5~15분, 이후 1~2분 | 관리자에게 받은 서명 파일 설치 (3-C) |
| EAS 클라우드 | `pnpm --filter mobile build:ios:dev-metro` → 10~15분 뒤 QR 로 설치 | 매번 10~15분 | 없음. 월 15회 한도 |

이 앱은 화면(JS)을 내장하지 않은 개발용 앱이다. 실행하면 첫 화면에 "Development Servers"
목록이 나오고, 맥에서 켠 서버를 고르면 붙는다.

> 개발 앱은 식별자가 `kr.co.everynook.app.dev` 라 스토어 앱(`kr.co.everynook.app`)과 한 폰에 같이 있는다.
> 아이콘에 DEV 표시가 있는 쪽이다.

### 2-2. 어느 서버를 볼지 고르기

**앱을 다시 깔지 않는다.** 맥에서 어떤 명령으로 서버를 켰느냐가 결정하고, 바꾸려면 서버만 재시작한다.

| 붙을 곳 | 맥에서 (레포 루트) | 언제 |
| --- | --- | --- |
| **내 로컬 웹** | `pnpm dev` | 웹 개발할 때 (기본) |
| 개발 웹 (`app-dev.everynook.co.kr`) | `pnpm dev:remote` | 셸만 고칠 때 |

로컬에서 만드는 앱은 언제나 **개발 앱**이고 개발 API 를 본다. 운영 웹·운영 API 는 여기서 보지 않는다 —
심사 전 확인은 TestFlight(4절)로 한다. 운영 웹에서만 나는 문제를 파야 하면
`EXPO_PUBLIC_WEB_URL=https://everynook.co.kr pnpm dev:remote` 로 개발 앱이 운영 웹을 보게 할 수는 있다 (FAQ).

**`pnpm dev` 가 하는 일** — 웹 서버(vite)와 앱 서버(Metro)를 같이 띄우고, 앱에게 "이 맥의 웹을 봐라"고
알려준다. 주소는 맥의 LAN IP 로 자동으로 만든다(폰은 `localhost` 를 모른다). 폰의 앱에서 서버를 고르면
붙고, 이제 **웹 코드를 저장하면 폰 화면이 바로 바뀐다.**

**실기기에서 로컬 웹을 볼 때는 HTTPS 가 필요하다** (#172). 한 번만 설정한다:

```bash
brew install mkcert
mkcert -install
ipconfig getifaddr en0                              # 맥 IP 확인, 예: 192.168.0.10
cd apps/web/certs && mkcert 192.168.0.10 localhost 127.0.0.1
```

생성된 키·인증서 경로를 `apps/web/.env.local` 의 `DEV_HTTPS_KEY` / `DEV_HTTPS_CERT` 에 넣으면
`pnpm dev` 가 알아서 `https://` 주소를 쓴다. 아이폰에 mkcert 루트 CA 를 설치·신뢰하는 절차는
[apps/web/certs/README.md](../../apps/web/certs/README.md). 시뮬레이터에서도 https 를 보려면
루트 CA 를 시뮬레이터에 넣는다: `xcrun simctl keychain booted add-root-cert "$(mkcert -CAROOT)/rootCA.pem"`.

주의:

- 주소가 바뀌었으면 `pnpm dev` 를 **다시 띄운다**. 앱만 새로고침하면 옛 주소를 본다
- 맥 IP 가 바뀌면 인증서(SAN)를 다시 만든다 (`DEV_HTTPS_*` 경로는 그대로)
- 특정 주소를 강제하려면 `EXPO_PUBLIC_WEB_URL=https://... pnpm dev`
- 지도 화면(`/map`)은 네이버 지도가 등록된 주소에서만 뜬다. `https://<IP>:5173` 을 관리자에게
  등록 요청. 지도 안 볼 거면 무시

### 2-3. 로그 보기

| 보고 싶은 것 | 방법 |
| --- | --- |
| **웹 콘솔·네트워크** (대부분) | 폰: 설정 › 앱 › Safari › 고급 › **웹 검사기** 켬. 맥: Safari › 설정 › 고급 › **웹 개발자용 기능 보기** 체크 → Safari 메뉴 개발자용 › 기기 이름 › 페이지 선택. 크롬 개발자도구처럼 쓴다 |

## 3. 네이티브 개발

### 3-0. 어디를 고치나 — `ios/` 는 절대 직접 고치지 않는다

| 고칠 것 | 실제 위치 |
| --- | --- |
| 네이티브 모듈 (세션, 키보드, 공유) | `apps/mobile/modules/*/ios/*.swift` |
| 공유 확장 화면 | `apps/mobile/targets/share-target/*.swift` |
| 권한, 아이콘, 식별자, 플러그인 | `apps/mobile/app.config.ts` |

`ios/`·`android/` 는 `app.config.ts` 를 재료로 **빌드마다 새로 생성**된다. Xcode 에서 직접 고치면
다음 빌드에 사라진다. Xcode 는 실행·디버깅용으로만 열고 편집은 위 경로에서.

네이티브 개발에는 세 가지 방법이 있다. **기본은 시뮬레이터**고, 나머지 둘은 실기기가 꼭
필요할 때다.

| 방법 | 한 번 고치고 다시 띄우는 시간 | 관리자 도움 | 무료 한도 |
| --- | --- | --- | --- |
| **A. 시뮬레이터** | 1~2분 | 불필요 | 안 씀 |
| B. EAS 빌드 → 실기기 | 10~15분 (+대기) | 기기 등록 1회 | **씀** (월 15회) |
| C. 케이블로 연결한 실기기 | 1~2분 | 기기 등록 + 서명 파일 1회 | 안 씀 |

### 3-A. 시뮬레이터 (기본)

```bash
pnpm ios          # 레포 루트에서
```

**`pnpm onboard` 을 먼저 해야 한다.** Firebase 설정 파일(`GoogleService-Info.plist`)이 없으면 시뮬레이터
빌드도 prebuild 단계에서 멈춘다 — 경고가 아니라 에러다. `pnpm onboard` 이 그 파일을 EAS 에서 받아온다.

- 첫 빌드 5~15분, 이후 **1~2분** (바뀐 파일만 다시 컴파일)
- 코드 서명이 없어서 Apple 계정·팀 선택·허가증 전부 무관. 관리자 도움 없이 바로 된다
- Xcode 로 `apps/mobile/ios/Nook.xcworkspace` 를 열면 **브레이크포인트·변수 확인·단계 실행**이 된다. 웹 개발자도구와 같은 수준
- 로컬 웹은 `pnpm dev` 로 그대로 본다 (시뮬레이터도 맥의 LAN IP 에 닿는다)

시뮬레이터에서 되는 것:

| 기능 | 동작 |
| --- | --- |
| 공유 확장, App Group | O |
| 카카오 로그인 | O (카톡 앱이 없어 웹 로그인으로) |
| 애플 로그인 | O (시뮬레이터에 iCloud 로그인 필요) |
| 푸시 알림 | Apple Silicon 맥 + Xcode 14 이상이면 O. 우리 FCM 경로는 미검증 |
| 카메라, 실제 성능 | X → 실기기 |

**네이티브 개발의 거의 전부는 여기서 끝난다.** 실기기는 마지막 확인용이다.

### 3-B. EAS 빌드로 실기기 (최종 확인용)

시뮬레이터가 못 하는 것(카메라, 실제 푸시, 성능)을 확인할 때. 2-1 절과 같은 방법이다.

```bash
pnpm --filter mobile build:ios:dev-metro          # 클라우드. 10~15분 + 대기. 한도 소모
pnpm --filter mobile build:ios:dev-metro:local    # 내 맥. 10~20분. 한도 안 씀. Xcode 필요
```

완료되면 QR 로 재설치한다. 한 줄 고치고 확인하는 루프로는 **쓸 수 없다** — 확인 한두 번용이다.

무료 한도: iOS 월 15회, 팀 전체 공유, 매월 1일 리셋. 초과하면 과금이 아니라 빌드가 막힌다.
로컬(`:local`)은 한도를 쓰지 않는다.

`:local` 은 gitignore 된 파일을 빌드에서 빼는 성질이 있어 Firebase 설정 파일이 누락된 적이 있다.
첫 로컬 빌드는 결과물을 확인한다:

```bash
unzip -o build/dev-metro.ipa -d /tmp/ipa
plutil -p /tmp/ipa/Payload/*.app/GoogleService-Info.plist | head -3
```

### 3-C. 케이블로 연결한 실기기

시뮬레이터처럼 1~2분 증분 빌드를 실기기에서 하는 방법이다. 카메라·푸시·공유 확장을 실기기에서
반복 확인할 때 쓴다.

**왜 준비물이 있나** — 우리 Apple 계정이 개인(Individual) 멤버십이라 팀원을 계정에 추가할 수 없다.
그래서 팀원 Xcode 는 실기기 서명에 필요한 허가증(인증서 + 프로파일)을 스스로 받아오지 못한다.
대신 관리자가 API 로 발급해 파일로 준다. **한 번만** 받으면 된다.

**처음 한 번**:

1. 맥에서 **키체인 접근** 앱 → 메뉴 "키체인 접근 › 인증서 지원 › 인증 기관에서 인증서 요청…" →
   이메일만 채우고 "디스크에 저장됨" 선택 → `CertificateSigningRequest.certSigningRequest` 파일이 생긴다.
   이 파일과 폰 UDID(2-1) 를 관리자에게 보낸다. 비밀 아니니 Slack 으로 보내도 된다
2. 관리자에게 파일 3개를 받는다 — `<이름>.cer`, `Nook Development.mobileprovision`,
   `Nook ShareExtension Development.mobileprovision`. 셋 다 비밀이 아니다 (개인키는 1번에서 내 맥 키체인에 만들어져 밖으로 안 나간다)
3. 세 파일을 **각각 더블클릭**한다. `.cer` 는 키체인에, `.mobileprovision` 은 Xcode 에 들어간다

**이후**:

```bash
pnpm ios:device        # 레포 루트에서. 폰은 케이블로 연결, 잠금 해제
```

- 맥에 팀 프로파일이 설치돼 있으면 `app.config.ts` 가 알아서 그걸로 서명한다. Xcode 에서 팀을 고르거나 설정을 만질 일이 없다
- 프로파일 설치 **전에** 만들어진 `ios/` 는 서명 설정이 없어서, 이 명령이 한 번 다시 만든다 (5~15분). 그다음부터 1~2분
- 시뮬레이터(`pnpm ios`)도 같은 `ios/` 를 쓴다. 번갈아 써도 다시 만들지 않는다
- 폰에서 "신뢰하지 않는 개발자" 가 뜨면 설정 › 일반 › VPN 및 기기 관리 에서 신뢰

허가증은 1년 뒤 만료된다. 그때 관리자가 새 프로파일을 주면 다시 더블클릭.

## 4. App Store Connect(TestFlight)에 올리기

팀원 맥에 Apple 키·인증서가 없어도 된다. 서명 자격증명과 App Store Connect API 키가
EAS 서버에 있어서 EAS 가 대신 서명하고 올린다.

```bash
pnpm --filter mobile build:ios:prod-store      # 스토어용 빌드 (JS 내장, Metro 불필요)
pnpm --filter mobile submit:ios:prod-store     # 최신 빌드를 App Store Connect 에 업로드
```

조건과 한계:

- EAS 계정 권한이 **Developer 이상**이어야 한다 (Viewer 는 빌드 불가)
- 스토어 빌드도 **월 15회 한도**에서 빠진다
- `eas submit` 은 무료 큐라 최대 1시간 기다릴 수 있다. 업로드가 끝나면 App Store Connect →
  TestFlight 에서 처리 상태를 본다
- 버전 번호는 EAS 가 자동으로 올린다 (`autoIncrement`)

관리자는 ASC 키가 맥에 있어 더 빠른 방법(altool, 1분)을 쓰지만 팀원은 위 명령으로 충분하다.
심사 제출·릴리스 절차는 [06. App Store 제출](06-App-Store-제출.md).

## 5. FAQ

**Xcode 팀 목록에 Nook 이 없고 인증서에 X 가 뜬다**
정상이다. 개인 계정이라 팀원을 추가할 수 없어 Xcode 의 자동 서명은 안 된다. 실기기는 관리자가 준
파일로 서명한다 (3-C). `apps/mobile/.env.local` 에 `APPLE_TEAM_ID` 가 있으면 지우고
`npx expo prebuild --clean`. 본인 Apple ID(Personal Team)로 우회하는 것도 안 된다 — 식별자와
App Group 이 어긋나 막힌다.

**`pnpm ios:device` 가 "팀 개발 프로파일이 이 맥에 없다" 로 멈춘다**
3-C 의 파일 3개를 안 받았거나 더블클릭을 안 했다. `.mobileprovision` 을 더블클릭하면 아무 창도 안 뜨는 게 정상이다.
설치됐는지는 `ls ~/Library/Developer/Xcode/UserData/Provisioning\ Profiles/` 로 본다.

**`pnpm ios:device` 가 "doesn't include the currently selected device" 로 실패한다**
그 폰의 UDID 가 등록되지 않았거나, 등록 뒤 새로 발급된 프로파일을 아직 안 받았다. 관리자에게 요청 (2-1).

**`pnpm ios:device` 가 "No signing certificate" / "no identity found" 로 실패한다**
`.cer` 가 키체인에 없거나, CSR 을 만든 맥이 아닌 다른 맥에서 빌드하고 있다. 인증서는 CSR 을 만든 맥의
개인키와 짝이라 그 맥에서만 쓸 수 있다. 다른 맥은 CSR 을 새로 만들어 다시 발급받는다.

**QR 을 찍었는데 설치가 안 된다**
그 폰의 UDID 가 등록되지 않은 경우다. 관리자에게 등록 요청 (2-1).

**`pnpm ios` 가 `Path to GoogleService-Info.plist is not defined` 로 실패한다**
`pnpm onboard` 을 안 했다. Firebase 설정 파일은 시뮬레이터 빌드에도 필수다. `pnpm onboard` 을 한 뒤
**반드시 `npx expo prebuild --clean` 을 거쳐** 다시 `pnpm ios`. 실패한 첫 빌드가 반쯤 만든 `ios/` 를
남기고, 다음 `pnpm ios` 는 `ios/` 가 있으면 다시 만들지 않아서 그대로 두면 pod install 이 SPM 오류로
계속 깨진다.

**카카오 로그인만 실패한다**
`pnpm onboard` 을 안 했거나 실패했다. 다시 실행.

**지도 화면이 깨진다**
`apps/web/.env.local` 의 `VITE_NAVER_MAP_CLIENT_ID` 가 비었거나, 실기기 + 로컬 웹인데 내 IP 가
네이버 콘솔에 등록되지 않은 경우. 관리자에게 요청.

**로컬 웹으로 바꿨는데 앱이 계속 개발 웹을 본다**
`pnpm dev:remote` 로 띄웠거나, 주소가 바뀐 뒤 `pnpm dev` 를 다시 띄우지 않았다.

**운영 웹에서만 나는 문제를 앱 안에서 봐야 한다**
`EXPO_PUBLIC_WEB_URL=https://everynook.co.kr pnpm dev:remote`. 개발 앱이 운영 웹을 보고 웹 검사기도 붙는다.
단, 앱 식별자는 개발 앱이라 운영 API 의 애플·카카오 로그인은 안 될 수 있다. 심사 전 확인은 이게 아니라 TestFlight(4절).

**실기기에서 로컬 웹이 안 열리거나 인증서 오류가 난다**
아이폰에 mkcert 루트 CA 가 설치·신뢰되지 않았다 (`apps/web/certs/README.md` 4~5단계).
그리고 `EXPO_PUBLIC_WEB_URL` 이 `https://` 인지, IP 가 인증서 만들 때 넣은 IP 와 같은지 본다.

**푸시가 안 온다**
시뮬레이터는 조건부(3-A 표). 확실한 확인은 실기기에서. 실기기에서도 안 오면 Firebase 설정
파일이 빌드에 들어갔는지(3-B 의 확인 명령) 본다.

**`pod install` 이 로케일 오류로 실패한다**
`export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` 후 재시도.

**`ios/` 를 고쳤는데 사라졌다**
생성 폴더다. 3-0 의 실제 위치에서 고친다.

**뭔가 꼬였다**
`cd apps/mobile && npx expo prebuild --clean && cd - && pnpm ios`

## 6. 관리자에게 요청할 것

| 언제 | 요청 |
| --- | --- |
| 처음 | GitHub 초대, EAS 초대(Developer 이상), `apps/web/.env.local` 값 |
| 실기기에 깔 때 | 폰 UDID + 기기 이름 → 등록 (폰당 1회) |
| 로컬 웹을 실기기에서 볼 때 | `https://<내 맥 IP>:5173` 을 네이버 지도 콘솔에 등록 |
| 실기기를 내 맥에서 직접 빌드할 때 | CSR 파일 → 인증서 + 프로파일 2개 (3-C, 맥당 1회) |
