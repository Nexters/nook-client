## 0. 먼저 — 이 앱이 뭔지

**우리 사이트만 열리는 전용 브라우저**다.

크롬이 네이버를 보여주듯, 우리 앱은 우리 웹(`apps/web`)을 받아와 보여준다. 화면은 앱 안에
없고 웹에 있다. 앱 자체에는 웹이 혼자 못 하는 얇은 기능만 들어있다 — 카메라, 푸시 알림,
다른 앱에서 공유받기, 로그인 세션 보관.

그래서 하는 일이 세 종류로 갈린다.

| 하는 일 | 고치는 곳 | 앱을 다시 만드나 |
| --- | --- | --- |
| 화면 고치기 | `apps/web/` | **아니오.** 저장하면 폰 화면이 바뀐다 |
| 앱 껍데기 JS 고치기 | `apps/mobile/src/` | **아니오.** 저장하면 바뀐다 |
| 네이티브 고치기 | `apps/mobile/modules/`, `targets/`, `app.config.ts` | **예.** 이때만 빌드 |

앞의 둘이 일의 대부분이고, **앱을 다시 만드는 일은 셋째 줄에서만 생긴다.**

이름 두 개만 알면 된다.

- **Metro / vite** — 맥에서 켜두는 서버. 폰의 앱이 이걸 보고 화면을 그린다. vite 는 웹, Metro 는 앱 껍데기 JS 담당. 코드를 저장하면 화면이 바뀌는 건 이 둘 덕분이다.
- **EAS** — 앱(전용 브라우저 자체)을 대신 만들어주는 Expo 의 클라우드. 네이티브를 고쳤을 때만 간다.

## 1. 처음 세팅 (한 번)

### 준비물

| 것 | 설치 | 언제 필요 |
| --- | --- | --- |
| 맥, 아이폰 | 폰과 맥이 **같은 Wi-Fi** | 항상 |
| Xcode | App Store. 용량이 크니 먼저 걸어둔다 | 시뮬레이터·네이티브 빌드 (3절) |
| CocoaPods | `brew install cocoapods` | 같음 |

웹만 만질 거면 Xcode 없이도 시작할 수 있다. 네이티브 개발을 하려면 필요하다.

### 레포

```bash
git clone git@github.com:Nexters/nook-client.git && cd nook-client
nvm install
corepack enable
pnpm install
```

### 값 채우기

```bash
cp apps/web/.env.example apps/web/.env.local     # 값은 관리자에게. 전부 공개값
```

앱 쪽 값(카카오 키, Firebase 설정 파일)은 커밋돼 있지 않다. EAS 계정에 초대돼 있으면
명령 한 줄로 내려온다.

```bash
cd apps/mobile
pnpm exec eas login
pnpm exec eas env:pull --environment production
```

이 명령이 `apps/mobile/.env.local` 을 새로 쓴다. **여기에 `APPLE_TEAM_ID` 는 넣지 않는다** —
넣으면 Xcode 서명이 깨진다 (FAQ 첫 항목).

## 2. 실기기에서 개발하기 + 서버 갈아타기

### 2-1. 폰에 앱 한 번 깔기

폰에 앱을 깔려면 Apple 허가증에 그 폰이 등록돼 있어야 한다. **폰 한 대당 한 번**이다.

1. 아이폰을 맥에 케이블로 연결 → Finder 사이드바에서 기기 클릭 → 이름 아래 정보를 **클릭**하면
   UDID 가 나온다. 기기 이름과 함께 관리자에게 전달
2. 관리자가 등록을 끝내면 EAS 빌드를 돌린다 (관리자 또는 본인):
   ```bash
   pnpm --filter mobile build:prod-metro
   ```
3. 10~15분 뒤 빌드 페이지의 **QR 을 아이폰 카메라로 찍어 설치**

이 앱은 화면(JS)을 내장하지 않은 개발용 앱이다. 실행하면 첫 화면에 "Development Servers"
목록이 나오고, 맥에서 켠 서버를 고르면 붙는다.

> 이미 스토어 앱(같은 식별자 `kr.co.everynook.app`)이 깔려 있으면 덮어써진다. 둘을 같이
> 두고 싶으면 관리자에게 `dev-metro` 빌드를 요청한다 — 식별자가 `.dev` 로 달라 공존한다.

### 2-2. 어느 서버를 볼지 고르기

**앱을 다시 깔지 않는다.** 맥에서 서버를 켤 때 정하고, 바꾸려면 서버만 재시작한다.

| 붙을 곳 | 맥에서 (레포 루트) | 조건 |
| --- | --- | --- |
| 운영 웹 | `pnpm mobile:start:prod` | 없음 |
| 개발 웹 | `pnpm mobile:start:dev` | 개발 웹(`app-dev.everynook.co.kr`)이 떠 있어야 함 |
| **내 로컬 웹** | 아래 | 웹 개발할 때 |

**로컬 웹 보기** — 폰은 맥의 `localhost` 를 모르니 맥의 내부 IP 로 접속한다. 실기기에서는
**HTTPS** 로 띄우는 것이 공식 절차다 (#172).

① 맥 IP 확인

```bash
ipconfig getifaddr en0        # 예: 192.168.0.10
```

② 로컬 HTTPS 인증서 (한 번)

```bash
brew install mkcert
mkcert -install
cd apps/web/certs && mkcert 192.168.0.10 localhost 127.0.0.1
```

생성된 키·인증서 경로를 `apps/web/.env.local` 의 `DEV_HTTPS_KEY` / `DEV_HTTPS_CERT` 에 넣는다.
아이폰에 mkcert 루트 CA 를 설치·신뢰하는 절차는 [apps/web/certs/README.md](../../apps/web/certs/README.md).

③ 서버 두 개

```bash
pnpm web:dev                                                          # 1 — https://192.168.0.10:5173
EXPO_PUBLIC_WEB_URL=https://192.168.0.10:5173 pnpm mobile:start:prod  # 2 — 앱 서버
```

폰의 앱에서 서버를 고르면 붙고, 이제 **웹 코드를 저장하면 폰 화면이 바로 바뀐다.**

주의:

- `EXPO_PUBLIC_WEB_URL` 은 위처럼 **명령 앞에 붙여** 넘긴다. `.env.local` 에만 써두면
  `start:prod`/`:dev` 가 variant 기본 주소로 덮어쓴다. `.env.local` 값을 쓰려면 `pnpm mobile:start`
- 주소를 바꾸면 **Metro 를 재시작**해야 한다. 앱만 새로고침하면 옛 주소를 본다
- 맥 IP 가 바뀌면 인증서(SAN)·`DEV_HTTPS_*`·`EXPO_PUBLIC_WEB_URL` 을 같이 갱신한다
- 지도 화면(`/map`)은 네이버 지도가 등록된 주소에서만 뜬다. `https://<IP>:5173` 을 관리자에게
  등록 요청. 지도 안 볼 거면 무시

### 2-3. 로그 보기

| 보고 싶은 것 | 방법 |
| --- | --- |
| **웹 콘솔·네트워크** (대부분) | 폰: 설정 › 앱 › Safari › 고급 › **웹 검사기** 켬. 맥: Safari › 설정 › 고급 › **웹 개발자용 기능 보기** 체크 → Safari 메뉴 개발자용 › 기기 이름 › 페이지 선택. 크롬 개발자도구처럼 쓴다 |
| 앱 껍데기 JS 로그 | `pnpm mobile:start` 터미널 |
| 네이티브(Swift) 로그·크래시 | 맥의 Console.app → 기기 선택 → 프로세스 이름으로 필터 |
| 개발자 메뉴 (리로드 등) | 폰을 흔든다 |

## 3. 네이티브 개발

### 3-0. 어디를 고치나 — `ios/` 는 절대 직접 고치지 않는다

| 고칠 것 | 실제 위치 |
| --- | --- |
| 네이티브 모듈 (세션, 키보드, 공유) | `apps/mobile/modules/*/ios/*.swift` |
| 공유 확장 화면 | `apps/mobile/targets/share-target/*.swift` |
| 권한, 아이콘, 식별자, 플러그인 | `apps/mobile/app.config.ts` |

`ios/`·`android/` 는 `app.config.ts` 를 재료로 **빌드마다 새로 생성**된다. Xcode 에서 직접 고치면
다음 빌드에 사라진다. Xcode 는 실행·디버깅용으로만 열고 편집은 위 경로에서.

네이티브 개발에는 세 가지 방법이 있다. **기본은 시뮬레이터**고, 나머지 둘은 실기기가 꼭
필요할 때다.

| 방법 | 한 번 고치고 다시 띄우는 시간 | Apple 허가증 | 무료 한도 | 상태 |
| --- | --- | --- | --- | --- |
| **A. 시뮬레이터** | 1~2분 | 불필요 | 안 씀 | 지금 가능 |
| B. EAS 빌드 → 실기기 | 10~15분 (+대기) | 등록 1회 | **씀** (월 15회) | 지금 가능 |
| C. fastlane match → 실기기 | 1~2분 | 자동 배포 | 안 씀 | **미구축** |

### 3-A. 시뮬레이터 (기본)

```bash
cd apps/mobile && pnpm ios
```

- 첫 빌드 5~15분, 이후 **1~2분** (바뀐 파일만 다시 컴파일)
- 코드 서명이 없어서 Apple 계정·팀 선택·허가증 전부 무관. 관리자 도움 없이 바로 된다
- Xcode 로 `apps/mobile/ios/Nook.xcworkspace` 를 열면 **브레이크포인트·변수 확인·단계 실행**이 된다. 웹 개발자도구와 같은 수준
- 로컬 웹을 보려면 `.env.local` 의 `EXPO_PUBLIC_WEB_URL=http://localhost:5173` (시뮬레이터는 localhost 가 그대로 맥이다. 웹을 HTTPS 로 띄웠다면 `https://localhost:5173`)

시뮬레이터에서 되는 것:

| 기능 | 동작 |
| --- | --- |
| 공유 확장, App Group | O |
| 카카오 로그인 | O (카톡 앱이 없어 웹 로그인으로) |
| 애플 로그인 | O (시뮬레이터에 iCloud 로그인 필요) |
| 푸시 알림 | Apple Silicon 맥 + Xcode 14 이상이면 O. 우리 FCM 경로는 미검증 |
| 카메라, 실제 성능 | X → 실기기 |

**네이티브 개발의 거의 전부는 여기서 끝난다.** 실기기는 마지막 확인용이다.

### 3-B. EAS 빌드로 실기기 (최종 확인용)

시뮬레이터가 못 하는 것(카메라, 실제 푸시, 성능)을 확인할 때. 2-1 절과 같은 방법이다.

```bash
pnpm --filter mobile build:prod-metro          # 클라우드. 10~15분 + 대기. 한도 소모
pnpm --filter mobile build:prod-metro:local    # 내 맥. 10~20분. 한도 안 씀. Xcode 필요
```

완료되면 QR 로 재설치한다. 한 줄 고치고 확인하는 루프로는 **쓸 수 없다** — 확인 한두 번용이다.

무료 한도: iOS 월 15회, 팀 전체 공유, 매월 1일 리셋. 초과하면 과금이 아니라 빌드가 막힌다.
로컬(`:local`)은 한도를 쓰지 않는다.

`:local` 은 gitignore 된 파일을 빌드에서 빼는 성질이 있어 Firebase 설정 파일이 누락된 적이 있다.
첫 로컬 빌드는 결과물을 확인한다:

```bash
unzip -o build/prod-metro.ipa -d /tmp/ipa
plutil -p /tmp/ipa/Payload/*.app/GoogleService-Info.plist | head -3
```

### 3-C. fastlane match 로 실기기 (미구축)

> ⚠️ 아직 만들지 않았다. 팀원이 실기기 네이티브 루프를 자주 필요로 하면 관리자가 구축한다.

**왜 필요한가** — 우리 Apple 계정이 개인(Individual) 멤버십이라 팀원을 계정에 추가할 수 없다.
그래서 팀원 Xcode 는 자동으로 허가증을 받아오지 못하고, 실기기 직접 빌드가 안 된다.

**무엇인가** — 허가증(인증서 + 프로파일)을 관리자가 한 번 발급해 **암호화된 비공개 저장소**에
넣어두고, 팀원은 명령 한 줄로 받아 설치한다. Apple 계정도 관리자 키도 필요 없다. 이 문제를
풀기 위한 업계 표준 도구다.

**도입 후 팀원이 할 일**:

```bash
fastlane match development --readonly    # 저장소에서 허가증 받기 (최초 1회, 폰 추가 시 재실행)
cd apps/mobile && pnpm ios --device      # 이후 1~2분 증분 빌드
```

**공유되는 것** — 개발용 인증서 하나. 등록된 폰에 설치하는 것 외엔 할 수 있는 게 없고,
스토어 배포용 인증서는 EAS 에 그대로 남아 팀원이 못 만진다. 문제 생기면 관리자가 폐기·재발급.

## 4. App Store Connect(TestFlight)에 올리기

팀원 맥에 Apple 키·인증서가 없어도 된다. 서명 자격증명과 App Store Connect API 키가
EAS 서버에 있어서 EAS 가 대신 서명하고 올린다.

```bash
pnpm --filter mobile build:prod-store      # 스토어용 빌드 (JS 내장, Metro 불필요)
pnpm --filter mobile submit:prod-store     # 최신 빌드를 App Store Connect 에 업로드
```

조건과 한계:

- EAS 계정 권한이 **Developer 이상**이어야 한다 (Viewer 는 빌드 불가)
- 스토어 빌드도 **월 15회 한도**에서 빠진다
- `eas submit` 은 무료 큐라 최대 1시간 기다릴 수 있다. 업로드가 끝나면 App Store Connect →
  TestFlight 에서 처리 상태를 본다
- 버전 번호는 EAS 가 자동으로 올린다 (`autoIncrement`)

관리자는 ASC 키가 맥에 있어 더 빠른 방법(altool, 1분)을 쓰지만 팀원은 위 명령으로 충분하다.
심사 제출·릴리스 절차는 [06. App Store 제출](06-App-Store-제출.md).

## 5. FAQ

**Xcode 팀 목록에 Nook 이 없고 인증서에 X 가 뜬다**
정상이다. 개인 계정이라 팀원 추가가 안 되는 구조라 그 맥에서 실기기 서명이 안 된다.
시뮬레이터(3-A)에는 영향 없다. `apps/mobile/.env.local` 에 `APPLE_TEAM_ID` 가 있으면 지우고
`npx expo prebuild --clean`. 본인 Apple ID(Personal Team)로 우회하는 것도 안 된다 — 식별자와
App Group 이 어긋나 막히고 다음 빌드에 초기화된다. 실기기는 2-1 또는 3-C.

**QR 을 찍었는데 설치가 안 된다**
그 폰의 UDID 가 등록되지 않은 경우다. 관리자에게 등록 요청 (2-1).

**카카오 로그인만 실패한다**
`eas env:pull` 을 안 했거나 실패했다. 다시 실행.

**지도 화면이 깨진다**
`apps/web/.env.local` 의 `VITE_NAVER_MAP_CLIENT_ID` 가 비었거나, 실기기 + 로컬 웹인데 내 IP 가
네이버 콘솔에 등록되지 않은 경우. 관리자에게 요청.

**로컬 웹으로 바꿨는데 앱이 계속 운영 웹을 본다**
`EXPO_PUBLIC_WEB_URL` 을 `.env.local` 에만 써두고 `start:prod` 를 썼거나(명령 앞에 붙여야 한다),
주소를 바꾸고 Metro 를 재시작하지 않았다.

**실기기에서 로컬 웹이 안 열리거나 인증서 오류가 난다**
아이폰에 mkcert 루트 CA 가 설치·신뢰되지 않았다 (`apps/web/certs/README.md` 4~5단계).
그리고 `EXPO_PUBLIC_WEB_URL` 이 `https://` 인지, IP 가 인증서 만들 때 넣은 IP 와 같은지 본다.

**푸시가 안 온다**
시뮬레이터는 조건부(3-A 표). 확실한 확인은 실기기에서. 실기기에서도 안 오면 Firebase 설정
파일이 빌드에 들어갔는지(3-B 의 확인 명령) 본다.

**`pod install` 이 로케일 오류로 실패한다**
`export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` 후 재시도.

**`ios/` 를 고쳤는데 사라졌다**
생성 폴더다. 3-0 의 실제 위치에서 고친다.

**뭔가 꼬였다**
`cd apps/mobile && npx expo prebuild --clean && pnpm ios`

## 6. 관리자에게 요청할 것

| 언제 | 요청 |
| --- | --- |
| 처음 | GitHub 초대, EAS 초대(Developer 이상), `apps/web/.env.local` 값 |

| 실기기에서 네이티브를 자주 고쳐야 할 때 | fastlane match 구축 (3-C) |

## 7. 용어

| 말 | 뜻 |
| --- | --- |
| Metro | 앱 껍데기 JS 를 폰에 실시간으로 보내는 맥의 서버 |
| vite | 웹 화면을 서빙하는 맥의 서버 |
| EAS | 앱을 대신 빌드·서명·업로드해주는 Expo 클라우드 |
| dev client / `prod-metro` | 화면을 내장하지 않고 Metro 에서 받아 실행하는 개발용 앱 |
| `prod-store` | 화면을 내장해 혼자 도는 스토어 제출용 앱 |
| prebuild | `app.config.ts` 로 `ios/`·`android/` 를 생성하는 단계 |
| UDID | 아이폰 한 대의 고유 번호 |
| 인증서 / 프로비저닝 프로파일 | "누가 서명했나" / "이 앱을 이 폰들에 깔아도 된다" — Apple 이 발급하는 허가증 세트 |
| Individual 멤버십 | 우리 Apple 계정 종류. 팀원 추가 불가 → 실기기 직접 서명의 원인 |
| fastlane match | 허가증 세트를 팀이 안전하게 공유하는 도구 |
