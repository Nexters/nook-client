> Web, Android Share Target, iOS Share Extension이 같은 서버 계약을 사용하면서도 각 플랫폼의
> 런타임과 인증 저장소를 침범하지 않도록 API 모듈의 책임과 경계를 정의한다.

## 결정 요약

- 서버의 OpenAPI 명세를 요청·응답 DTO와 enum의 원본으로 사용한다.
- HTTP 전송, 서버 DTO, DTO Mapper, 화면 모델을 분리한다.
- Web의 생성 API 함수는 `shared/api`의 전송 계층을 사용한다.
- Android와 iOS는 TypeScript 코드를 공유하지 않고 같은 OpenAPI 계약으로 각자 생성한다.
- HTTP 클라이언트는 refresh token을 저장하거나 갱신하지 않는다.
- 생성 코드는 직접 수정하지 않고, 수동 코드는 생성 코드 디렉터리를 import만 한다.

## 모듈 경계

### Web

```text
apps/web/src/
├── shared/api/
│   ├── http.ts          # fetch, Base URL, 헤더, timeout, HTTP 오류
│   ├── contracts.ts     # Orval 생성 응답을 해석하는 공통 구조 타입
│   ├── response.ts      # ApiResponse<T> unwrap
│   ├── error.ts         # 플랫폼 공통 클라이언트 오류
│   └── generated/       # Orval 생성 DTO·enum·API 함수
└── features/<domain>/
    ├── api/             # endpoint 함수와 DTO → 화면 모델 Mapper
    ├── queries/         # TanStack Query option/hook
    └── types.ts         # 화면이 소비하는 모델
```

의존 방향은 `UI → Query → feature API → shared API/generated DTO` 한 방향이다. 생성 DTO를
컴포넌트에 직접 전달하지 않는다. 서버 필드명이나 enum이 바뀌어도 Mapper 아래에서 변경을
막기 위함이다.

### Android Share Target

```text
modules/share-target/android/.../share/
├── api/generated/       # OpenAPI Kotlin DTO
├── api/ShareApiClient   # HTTP 전송과 오류 변환
├── data/ShareRepository # 그룹 조회·생성·게시물 생성 흐름
├── model/               # Compose 화면 모델과 Mapper
└── ShareScreen          # UI 상태와 이벤트
```

### iOS Share Extension

```text
targets/share-target/
├── Api/Generated/       # OpenAPI Swift DTO
├── Api/ShareApiClient   # URLSession 전송과 오류 변환
├── ShareRepository      # 그룹 조회·생성·게시물 생성 흐름
├── ShareModels          # SwiftUI 화면 모델과 Mapper
└── ShareScreen          # UI 상태와 이벤트
```

네이티브 생성 코드는 각 Share Target에 필요한 모델만 포함한다. Web의 TanStack Query와
TypeScript API 모듈은 네이티브 확장에서 재사용하지 않는다.

## 환경별 Base URL

| 플랫폼 | 개발 | Preview/운영 | 주입 위치 |
| --- | --- | --- | --- |
| Web | `https://api-dev.everynook.co.kr/api/v1` | 배포 환경 API | `VITE_API_BASE_URL` |
| Android | dev API | 빌드 variant별 API | Gradle BuildConfig |
| iOS | dev API | 빌드 configuration별 API | xcconfig/Info.plist |

Base URL은 API 버전 경로와 마지막 슬래시까지 포함하는 공개 설정값이며 토큰이나 Client Secret을
넣지 않는다. 기능 코드는 상대 경로만 전달하고, URL 조합은 플랫폼의 API Client 한 곳에서
담당한다.

## 응답 규격

일반 도메인 API는 다음 공통 응답을 사용한다.

```ts
type ApiResponse<T> =
  | { resultType: 'SUCCESS'; success: T }
  | { resultType: 'FAIL'; error: { errorCode: string; reason: string; data?: unknown } };
```

인증 API의 성공 응답은 현재 공통 래퍼 없이 DTO를 직접 반환한다. 따라서 HTTP 전송 계층은
JSON을 임의로 unwrap하지 않는다. 일반 도메인 API만 `unwrapApiResponse`를 명시적으로
호출한다.

서버에는 아래 두 오류 포맷이 공존하므로 `ApiClientError` 하나로 정규화한다.

```text
신규: { resultType: "FAIL", error: { errorCode, reason, data } }
인증: { code, message, fieldErrors }
```

## 인증과 토큰 갱신 책임

- API Client는 주입받은 `AccessTokenProvider`로 access token만 읽는다.
- 브라우저 저장소에 refresh token을 직접 저장하지 않는다.
- 인증 세션 모듈이 토큰의 안전한 저장, refresh 단일화, 로그아웃을 소유한다.
- 보호 API는 `auth: 'required'`, 공개 API는 기본값 `auth: 'none'`을 명시한다.
- 401 발생 시 인증 세션 모듈이 한 번만 갱신한 후 원 요청을 한 번 재시도한다.
- 재시도도 401이면 세션을 제거하고 로그인 상태로 전환한다.
- API Client는 외부 출처 요청에 Authorization 헤더를 전달하지 않는다.

401 갱신과 재시도 구현은 인증 세션 작업에서 `AccessTokenProvider` 위에 추가한다. HTTP
클라이언트가 refresh token을 소유하면 WebView, 본앱, Share Extension의 세션 경계가
뒤섞이므로 여기서는 구현하지 않는다.

## 오류 처리 규칙

| 상황 | 클라이언트 처리 |
| --- | --- |
| 요청 전 인증 없음 | `AUTH_REQUIRED`, 네트워크 요청하지 않음 |
| 400 | 필드 오류를 폼에 표시 |
| 401 | 인증 모듈에서 refresh 후 1회 재시도 |
| 403 | 재시도 없이 권한 오류 표시 |
| 404 | 기능별 빈 상태 또는 찾을 수 없음 처리 |
| 409 | 서버의 안정적인 오류 코드로 기능 메시지 표시 |
| 429, 5xx | HTTP 계층 자동 재시도 없음, Query/기능 정책에서 결정 |
| timeout | 재시도 가능한 연결 오류 표시 |
| fetch 실패 | 오프라인·네트워크 오류 표시 |
| 응답 계약 불일치 | 사용자에게 일반 오류, 개발 환경에 진단 정보 기록 |

## DTO와 화면 모델

DTO는 서버 계약을 그대로 표현하고 화면 모델은 UI 의미를 표현한다. 서버 필드명, enum, nullable
규칙을 화면 컴포넌트가 직접 알지 않도록 기능 모듈의 Mapper에서 변환한다. 구체적인 DTO와
Mapper는 각 도메인 API 연동 작업에서 추가한다.

## 생성 코드 정책

- 원본: 서버가 배포한 `/v3/api-docs`의 OpenAPI JSON
- 생성물: Web TypeScript, Android Kotlin, iOS Swift DTO와 enum
- 직접 수정: 금지
- 수동 코드: API Client, 인증 연결, Mapper, Repository, Query Hook
- 커밋 여부: 앱 빌드가 생성 도구 없이 재현되도록 생성물을 커밋
- 검증: CI에서 명세로 재생성한 뒤 diff가 있으면 실패

OpenAPI에 내부 계산 프로퍼티, 누락된 security scheme, 실제와 다른 응답 코드가 있으면 생성 전에
서버 명세를 먼저 수정한다. 클라이언트 생성 설정에서 임시로 숨긴 필드는 목록과 제거 조건을 함께
기록한다.
