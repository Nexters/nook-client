EAS Build는 Expo 서버에서 iOS 앱을 빌드하고, EAS Submit은 완성된 빌드를 App Store Connect로
업로드한다. 클라우드 빌드와 제출만 수행하는 PC에는 Xcode가 필요하지 않다. 로컬에서 iOS 앱을
실행하거나 로컬 빌드를 만들 때는 macOS와 Xcode가 필요하다.

## 필요한 접근 권한과 파일

새 PC를 설정하기 전에 다음 항목을 준비한다.

- 저장소 접근 권한
- Expo의 `everynook` 프로젝트 접근 권한
- App Store Connect API Key의 `.p8` 파일
- 해당 키의 Key ID와 Issuer ID
- App Store Connect에서 nook 앱을 관리할 수 있는 역할

현재 Apple Developer Program은 Individual 멤버십이다. 초대받은 Admin 사용자는 App Store
Connect에서 앱과 제출을 관리할 수 있지만 Apple Developer의 Certificates, Identifiers & Profiles
권한까지 받는 것은 아니다. 기존 서명 인증서와 프로비저닝 프로파일을 EAS에서 재사용할 때는 문제가
없지만, 새로 만들거나 복구해야 할 때는 Account Holder인 팀장이 처리해야 한다.

제출용 API 키는 `App Manager` 역할이면 충분하다. 현재 Admin 키도 동작하지만 권한이 더 넓으므로,
키를 다시 발급할 때는 최소 권한의 Team Key를 권장한다.

## 1. 개발 도구 설치

저장소를 clone한 뒤 루트에서 Node와 pnpm 버전을 맞추고 의존성을 설치한다.

```bash
cd nook-client
nvm install
nvm use
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install --frozen-lockfile
```

설치 결과를 확인한다.

```bash
node --version
pnpm --version
```



## 2. Expo 로그인

모바일 앱 디렉터리에서 EAS CLI로 로그인한다. 전역 EAS CLI 대신 저장소에 설치된 버전을 사용한다.

```bash
cd apps/mobile
pnpm exec eas login
pnpm exec eas whoami
```

로그인한 Expo 계정이 `everynook/nook` 프로젝트에 접근할 수 있어야 한다. 권한이 없다면 Expo
조직에서 먼저 초대받는다.

## 3. App Store Connect API 키 설정



### 키 보관

`.p8` 파일은 Git 저장소 밖의 개인 디렉터리에 보관한다. 예시는 다음과 같다.

```text
~/.config/nook/apple/AuthKey_<KEY_ID>.p8
```

`.p8` 파일은 App Store Connect에서 한 번만 다운로드할 수 있다. Git, 메신저, 이메일에 올리지
않고 비밀번호 관리자나 승인된 비밀 공유 수단으로 전달한다. 파일 권한도 현재 사용자만 읽도록
제한한다.

```bash
chmod 600 ~/.config/nook/apple/AuthKey_<KEY_ID>.p8
```



### zsh 환경변수

새 PC의 `~/.zshrc`에 다음 값을 추가한다. 실제 Key ID와 Issuer ID는 App Store Connect의 발급
화면에서 확인한다.

```bash
export EXPO_ASC_API_KEY_PATH="$HOME/.config/nook/apple/AuthKey_<KEY_ID>.p8"
export EXPO_ASC_KEY_ID="<KEY_ID>"
export EXPO_ASC_ISSUER_ID="<ISSUER_ID>"
```

현재 터미널에 적용한다.

```bash
source ~/.zshrc
```

값을 노출하지 않고 설정 여부와 파일 존재 여부를 확인한다.

```zsh
for name in EXPO_ASC_API_KEY_PATH EXPO_ASC_KEY_ID EXPO_ASC_ISSUER_ID; do
  if [[ -n ${(P)name} ]]; then
    echo "$name: set"
  else
    echo "$name: missing"
  fi
done

[[ -f "$EXPO_ASC_API_KEY_PATH" ]] && echo ".p8: exists" || echo ".p8: missing"
```

세 환경변수는 앱 번들 환경변수가 아니라 EAS CLI의 제출 인증값이다. `EXPO_PUBLIC_` 접두사를
붙이지 않고 `.env.example`, `eas.json`, 소스 코드에 실제 값을 기록하지 않는다.

`apps/mobile/eas.json`은 실행 중인 셸에서 아래 값을 받아 제출 프로필을 구성한다.

```json
{
  "ascApiKeyPath": "$EXPO_ASC_API_KEY_PATH",
  "ascApiKeyId": "$EXPO_ASC_KEY_ID",
  "ascApiKeyIssuerId": "$EXPO_ASC_ISSUER_ID"
}
```



## 4. 배포 전 검사

저장소 루트에서 변경 상태와 전체 검사를 확인한다.

```bash
git status --short
pnpm check
```

릴리스 전에 `apps/mobile/native-public-config.json`의 `apiBaseUrl`·`webUrl`(variant별)과
`apps/mobile/eas.json`의 App Store Connect 앱 ID도 확인한다. 특히 production `apiBaseUrl`이
이번 릴리스가 사용할 서버를 가리키는지 확인해야 한다.

Expo 앱 설정이 정상적으로 평가되는지는 다음 명령으로 확인한다.

```bash
cd apps/mobile
pnpm exec expo config --json
```



## 5. iOS production 빌드

모바일 앱 디렉터리에서 production 빌드를 실행한다.

```bash
cd apps/mobile
pnpm build:prod-store
```

실행되는 명령은 다음과 같다.

```bash
pnpm exec eas build --platform ios --profile prod-store
```

production 프로필은 App Store 배포용으로 빌드하며 build number를 자동 증가시킨다. 빌드가
완료되면 EAS Build 페이지의 Build ID, Git commit, 앱 버전과 build number를 기록한다.

최근 production 빌드는 다음 명령으로 다시 확인할 수 있다.

```bash
pnpm exec eas build:list \
  --platform ios \
  --build-profile prod-store \
  --status finished \
  --limit 5
```

특정 빌드의 상세 정보는 Build ID로 확인한다.

```bash
pnpm exec eas build:view <EAS_BUILD_ID>
```



### 서명 자격 증명 오류

EAS에 저장된 Distribution Certificate와 Provisioning Profile이 유효하면 다른 PC에서도 그대로
빌드할 수 있다. 다음 상황에서는 Individual 멤버십의 Account Holder인 팀장이 EAS 자격 증명을
복구해야 한다.

- Distribution Certificate 만료 또는 폐기
- Provisioning Profile 만료 또는 capability 불일치
- 새 Bundle ID나 Share Extension 추가
- Sign in with Apple 또는 App Group 설정 변경

팀장이 모바일 앱 디렉터리에서 다음 명령을 실행해 iOS 자격 증명을 관리한다.

```bash
pnpm exec eas credentials --platform ios
```

App Store Connect API 키는 앱 업로드 인증이고, iOS 코드 서명 문제를 항상 해결해 주는 것은 아니다.

## 6. App Store Connect 제출



### 최신 빌드 제출

`submit:prod-store`는 가장 최근의 iOS EAS 빌드를 선택한다. 다른 사람의 빌드나 이전 commit을 잘못
제출하지 않도록 먼저 `eas build:list`에서 대상 빌드를 확인한다.

```bash
cd apps/mobile
pnpm submit:prod-store
```

실행되는 명령은 다음과 같다.

```bash
pnpm exec eas submit --platform ios --profile prod-store --latest
```



### Build ID로 제출

여러 명이 동시에 빌드하거나 대상 빌드를 명확히 고정해야 한다면 `--latest` 대신 Build ID를
지정하는 방법이 더 안전하다.

```bash
pnpm exec eas submit \
  --platform ios \
  --profile prod-store \
  --id <EAS_BUILD_ID>
```

제출 상태와 App Store/TestFlight 상태를 확인한다.

```bash
pnpm exec eas submit:list --platform ios --limit 5
pnpm exec eas submit:status --platform ios --profile prod-store
```

EAS Submit 완료는 바이너리가 App Store Connect에 업로드됐다는 뜻이다. Apple의 빌드 처리가 끝난
뒤 TestFlight 배포, 심사 정보 입력, App Review 제출과 실제 출시는 App Store Connect에서 별도로
진행한다.

## 7. 오류 해결



### `expo config --json exited with non-zero code: 1`

```bash
pnpm exec expo config --json
```

위 명령으로 실제 설정 평가 오류를 확인한다. `app.config.ts`는 로컬 전용 비밀값이 없어도 평가될
수 있어야 한다. URL·번들 ID 등 공개 네이티브 설정은 `native-public-config.json`, 빌드 프로필과
제출 설정은 `eas.json`에서 관리한다.

### `ascApiKeyPath`, `ascApiKeyId`, `ascApiKeyIssuerId`가 비어 있음

- `~/.zshrc`에서 세 값을 `export`했는지 확인한다.
- 새 터미널을 열거나 `source ~/.zshrc`를 실행한다.
- `.p8` 경로에 공백이 있다면 값을 큰따옴표로 감싼다.
- `EXPO_ASC_API_KEY_PATH`가 실제 파일을 가리키는지 확인한다.



### App Store Connect `401 Unauthorized`

- `.p8`, Key ID, Issuer ID가 같은 API 키의 값인지 확인한다.
- 키가 App Store Connect에서 revoke되지 않았는지 확인한다.
- 새 키를 발급했다면 `.zshrc`의 세 값을 모두 함께 교체한다.



### App Store Connect `403 Forbidden`

- API 키 역할이 `App Manager` 또는 `Admin`인지 확인한다.
- 해당 키 또는 사용자에게 nook 앱 접근 권한이 있는지 확인한다.
- Account Holder가 최신 Apple 계약을 승인했는지 확인한다.



### 앱을 찾지 못함

아래 두 값이 App Store Connect의 nook 앱과 일치하는지 확인한다.

```text
Bundle ID: kr.co.everynook.app
App Store Connect 앱 ID: 6798223287
```



### 잘못된 최신 빌드를 선택함

`pnpm submit:prod-store`를 중단하고 `eas build:list`로 올바른 Build ID를 확인한 뒤 `eas submit --id`로
다시 제출한다.

## 8. 키 교체와 PC 폐기

API 키를 revoke하거나 교체한 경우 해당 키를 사용하는 모든 PC의 `.zshrc`와 `.p8` 파일을 함께
갱신한다. PC를 반납하거나 폐기할 때는 `.p8` 파일과 셸 설정을 제거한다. 분실하거나 외부에 노출된
키는 즉시 App Store Connect에서 revoke하고 새 키를 발급한다.
